# 第二百九十七次安装：v1170 真人好友入口解耦修复

本包是私人版本全新候选：公开网页保持 v1169 不变，私人内置页面为 v1170，私人 iOS 为 1.0.297 (297)，原生桥 35。请完整解压到新的目录后再用 Xcode 打开，不要覆盖或混用旧工程、旧 ZIP、旧 DerivedData 中的产物。

## 这次改了什么

- 本次诊断明确记录到：真人好友同步卡在资料确认阶段约 180 秒，未进入消息拉取和合并；同次授权检查约 1.8 秒，身份同步已跳过，因此这次不是 `licenseSyncManagedIdentities` 的 19 秒问题。
- 打开真人好友聊天只立即拉消息，不再强制生成头像和上报个人资料；资料在线心跳改为空闲后台任务，不能阻塞消息同步。
- 私聊首次只渲染最近 60 条，历史消息按 60 条逐批展开；聊天记录、好友关系、图片和密钥均不删除。
- 已读处理延后到首屏出现之后并分批执行；回执逐个排队发送，不再一次并发大量请求。
- 新诊断会分别显示 `chatOpen`、`chatRender`、`readMark`、`profilePayload` 和 `profileUpsert` 的耗时与数量，不采集聊天正文或头像内容。

## Mac 覆盖安装

1. 把 ZIP 完整解压到一个全新目录，不要直接在压缩包内打开工程。
2. 打开 `PhoneCompanionTest.xcodeproj`。
3. Target 版本必须显示 1.0.297、Build 297；签名使用原来的 Team 和 Bundle Identifier。
4. 不要先删除手机上的旧 App，直接对原来同一台 iPhone 执行 Run，以保留现有数据容器。
5. 启动后在版本页核对：网页核心 v1170、私人 iOS 1.0.297 (297)、原生桥 35。

## 这次怎么观察

1. 正常使用，不必反复重启，也不必故意频繁切页面。
2. 重点打开有较多历史记录的真人好友私聊，确认首屏可操作、能发送消息，向上点“查看更早消息”后旧记录仍在。
3. 如果再次出现明显卡顿，当时直接复制诊断，不用等待十五分钟，也不要先重启或切换页面。
4. 诊断若显示 `phoneFriend.chatOpen.end` 或 `chatRender.end` 很长，说明入口渲染仍是问题；若 `profilePayload`／`profileUpsert` 很长但消息同步仍完成，说明资料心跳已被隔离但自身仍需继续修；若这些都不长，则转查诊断里卡顿前的其它操作。

当前只完成 Windows 代码与自动测试；尚未在 Mac 编译、签名或覆盖安装，也尚未证明真实 iPhone 的间歇卡顿已经消失。
