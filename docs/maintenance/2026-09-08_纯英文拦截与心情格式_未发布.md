# 纯英文拦截与心情格式 未发布

## 用户确认的范围

网页和私人版共有。纯英文且没有中文翻译的角色回复，在原文输出开关开启和关闭时均拦截，覆盖线上微信、单次约会、共同生活主角与配角、电话、后台生成与收件。正常中文和带中文翻译的外语内容保留。关闭原文开关时，其余既有处理不变；开启时，其余既有原文行为不变。

心情和内心只加强提示词：半角方括号、半角竖线、完整闭合、单独一行、不嵌套、不把标签或格式示例复述为对白。原有不使用标签或要求 JSON 的场景仍沿用原协议。没有修改心情解析、心情拦截诊断比较或存档字段，不能承诺提示词百分之百约束模型。

空回复原因、重试、可见消息计数及 got 判断均未修复。私人后台 AI 政策拒绝的原策略保留，不扩展为网页中文出戏拦截。未完成快捷指令草稿和私人智能家居现场保持不动。

## 实现和影响面

- 两份 app.js：新增无副作用的正文语言检测和可选角色请求门禁；普通模型测试、总结、图片提示等未标记请求不受影响。请求被识别为纯英文时保留系统错误，不执行本轮功能标签。
- 网页线上请求、线下请求包装器及两边电话接入门禁。私人单次约会仍走直接 chatAPI，已逐项补齐主请求和原有纠正请求，不把网页实现整份覆盖私人实现。
- 两份 cohab-theater.js：配角 JSON 仅检测 bubbles 内正文，不把字段名当作英文正文，也不改变原有 JSON 协议。
- 后台 phone-role-push：英文检查在动作、outbox 与 APNs 之前，返回 english-only-output；保留私人拒绝原因优先级，英文终止不进入后台任务重试。新后台代码尚未部署。
- 客户端后台收件：英文旧队列不生成气泡、不通知、不执行动作；保存错误元数据并按原有持久化后确认机制消费。
- 网页和私人拦截记录的手动释放入口不能绕过英文检查，不重新执行标签。

检测会排除心情、记忆和操作标签等元数据，避免中文标签被误当作英文正文的翻译。结构化正文支持常见 content/text/body/bubbles 及 translation/trans 字段。判断依据是可见内容的文字字符，不是语义翻译质量鉴定；中英混合内容不会被一概当作纯英文。纯数字、表情和纯功能指令不在本次英文规则中。

## 验证

旧基线 9defbd8b 的双入口单元回归先出现 Missing expected rejection；隔离浏览器旧代码在开启原文时实际送达英文，新的零英文气泡断言失败。新代码同断言通过。

check_role_english_policy.cjs：网页及私人各覆盖开关两态的线上、约会、共同生活、电话，共 16 组合；带译文语音保留；后台两态收件均无气泡、无通知、无动作，错误和确认存在。check_chat_authorized_phone.cjs：两边权限和已有笔记 16 组合、输入和让 TA 回、自动查看及持久化恢复通过。check_reply_output_experiment.cjs：两边原文/关闭恢复、心情、合法来电和 X 标签、线下与剧场协议、设置持久化通过。

全量测试结果以 .qa/english-policy-tests.xml 最终结果为准。模型、RPC、原生通道均为隔离夹具，不是真实模型、真实 APNs 或 iPhone 验收。发布前必须统一新版本、重新完整验证，并部署新版后台；现在不能声称线上已经修复。

## 检查中发现并处理的问题

私人约会不经过网页的 offlineReplyChatRequest，只改包装器会漏掉私人约会，真实入口测试捕获后已补齐。后台 prompt 有固定时间字段索引，因此心情规则追加到数组末尾，不在数组头部插入，以免破坏关闭时间感知。旧 VM 测试需加载新检测函数；旧网页允许英文的预期按用户新规则更新，私人拒绝识别的优先级和中文角色边界测试保留。
