# v1237 大备份分段读写核验

日期：2026-09-12。线上起点为 `1f4b761bf5ba9264b94f3dd0fd3367deb4d7a7b6`（v1236）。本轮只发布网页；私人内置网页同步公共源码，原生仍为 iOS 1.0.355（355）、桥 37，不制作私人包。

## 事实与归因边界

- 用户截图明确报出“完整备份生成失败：Invalid string length”，失败发生在备份生成阶段，尚未进入下载函数。
- v1232 至 v1236 文件导出均会把完整对象序列化成单一字符串；当前导出还会集中读取并回填所有持久化图片。旧文件导入使用 FileReader.readAsText + JSON.parse，整个文件文本与解析对象、图片整理副本可能同时占用内存。
- 从 v1236 提取实际 exportData 函数，以约 520 MiB 备份运行，复现相同 Invalid string length；旧代码在限制字符串预算的行为回归中也失败。
- 私人内置源码并非没有这条大字符串路径。私人运行容器、原生存储、保存节流、实际数据和可用内存不同，用户报告私人版本正常不能证明相同源代码在所有数据量上安全。
- 导入白屏与重启符合上述内存风险，但没有目标手机的进程崩溃日志，不把推断写成已证实的唯一原因。
- 更正 v1236 记录：上午 11 点成功只能说明当时该环境能导出，不能排除备份大小、内容及内存变化；此前直接把故障归因于 v1233 下载按钮改动，证据不足。v1233/v1234/v1236 的真机失败历史保留。

- 新增行为测试：旧 JSON 语义、Unicode 与转义边界、重复图片复用、三种聊天归档还原、损坏文件/配额失败不发布状态、失败重试、暂存图片清理。
