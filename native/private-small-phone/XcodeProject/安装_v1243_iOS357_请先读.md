# 小手机 v1243 / iOS 1.0.357（357）安装与验收

这是 Mac 待编译的私人源码覆盖包，不是 IPA。公开网页同步为 v1245（共同生活旁白截断修复）；私人内置源码只同步了这一处最小必要改动，其余业务字节仍是 v1242 基线，不含 v1241–v1245 期间网页单独发布过的其他修复。

## 本次修了什么

共同生活 / 线下场景里，角色回复被模型输出长度截断时，最后一句如果正好是旁白（以【、（或(开头但没有等到闭合括号），会被当成普通台词，连同没闭合的括号一起显示成对话气泡，而不是旁白样式。

修复只改了两处解析函数：`offNarrationText`（正常解析路径）和 `modelUnfilteredOfflineItems`（"原文输出实验"开关打开时的路径）。现在只要一段文本是以【（(开头、但到结尾都没等到对应的】）)，就会被当作旁白处理，并去掉那个多余的开头括号；不需要重新生成，也不影响正常闭合的旁白和台词判断。

## 安装步骤

1. 在 Mac 把压缩包解压到一个全新的目录。不要覆盖旧工程目录，也不要先删除 iPhone 上的旧小手机。
2. 打开 `PhoneCompanionTest.xcodeproj`，沿用原 Apple Account、Team、Bundle ID、签名和现有 entitlement（HomeKit、Screen Time、通知等不受影响）。
3. 核对所有 Target 的 Marketing Version 均为 `1.0.357`，Build 均为 `357`，原生桥契约仍为 `38`，然后覆盖安装到真实 iPhone。
4. 打开"设置 → 授权与数据"，核对版本显示为私人 `1.0.357 (357)`。

## 验收

在共同生活里多聊几轮，直到出现一条比较长、容易被截断的旁白式回复（角色的动作、神态描写），确认：
- 完整闭合的旁白（【……】）继续按旁白样式显示，不受影响；
- 如果角色这次的最后一句旁白确实被截断（没有闭合括号），现在应该仍然按旁白样式显示，且开头不再残留一个孤零零的【；
- 普通对话台词气泡不受影响。

Windows 上已跑过全量自动化回归（除两项与本次改动无关的既有环境限制外全部通过）以及新增的截断旁白解析单测；Mac 编译、签名和真实 iPhone 上的实际验收仍待完成，不能据此直接称真机已经修好。
