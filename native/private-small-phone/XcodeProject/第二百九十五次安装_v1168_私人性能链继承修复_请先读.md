# 第二百九十五次安装：v1168 私人性能链继承修复候选

本包是全新私人候选：内置页面 v1168、私人 iOS 1.0.295 (295)、原生桥 35。

## 安装边界

- 这是 Mac 待编译源码包，不是已经签名的 IPA。
- 完整解压到一个新目录，只打开本包内的 `PhoneCompanionTest.xcodeproj`。
- 不要把文件逐个覆盖进旧工程，不要复用旧 ZIP 或旧 DerivedData 里的产物。
- 覆盖安装时不要先删除手机上的旧 App；本次代码不主动清除聊天、角色、图片、组件、登录信息或密钥。
- 公开网页源码与网页版本没有修改，也不需要发布网页。

## 这次实际修复

1. 真人小手机好友大量消息同步改为分批处理，并只核对受影响会话，避免一次同步持续占住 WebContent。
2. 自动授权检查延后并避开正在切页的时段；身份没有变化时不再重复同步 AI 和真人好友身份。
3. 原生授权网络与 JSON 解析使用 `URLSession.dataTask`，只在最终回传网页时进入主线程。
4. 启动、发热和事件循环保护期间暂停可选自动轮询；回前台先等待，再执行非强制快照。
5. WebContent 被系统终止后，等待并复核温度，再新建 `WKWebView`，不在已经终止的旧页面上重载。
6. 诊断可区分好友同步、授权网络、解析、回传及页面重建阶段，但不记录聊天正文、图片、网址、密钥或授权令牌。

本次仍保留 v1167 的心动审判、共同生活入口容错和删除推文后清理旧记忆。

## Mac 编译与覆盖安装

1. 关闭旧工程窗口，完整解压本包。
2. 在 Xcode 打开本包内的 `PhoneCompanionTest.xcodeproj`。
3. Target 版本必须显示 1.0.295、Build 295；运行后的诊断必须显示网页 v1168、私人 iOS 1.0.295 (295)、原生桥 35。
4. 选择原来同一 Team、同一 Bundle Identifier 和同一台 iPhone，先 `Product > Clean Build Folder`，再直接 Run 覆盖安装。
5. 安装前不要删除手机 App。打开后先确认聊天、真人好友、群聊、三个主页组件和登录状态仍在。

## 本轮观察方法

- 正常使用，不需要一直停在诊断页，也不要主动反复重启。
- 如果再次出现明显延迟或发热，当时立刻打开“设置 → 私人 App 性能保护 → 查看卡顿诊断”并复制；不要等它恢复后再复制。
- 如果整页已像图片一样完全不能点，先保留现场；若原生恢复面板出现，可点“继续等待”。页面恢复后再复制诊断。
- 新诊断重点看 `phoneFriend.*`、`license.*`、`native.license.request.*`、`performance.guard`、`native.webcontent.remount*`。同一次卡顿能对应到哪个阶段，才是继续缩小范围的证据。
