# v1226 明确语音请求修复发布核验

2026-09-09 用户要求修复“角色想发语音却落成文字；再次要求发语音仍是文字”，并授权网页线上发布和私人源码包打包。本轮属于网页与私人版共有的普通微信回复类型修复；私人 iOS 版本为 1.0.349（349），原生桥仍为 37。

## 已确认根因与修复

- 旧逻辑把“平时语音频率为 0”错误扩大成“用户明确要求时也禁止语音”，导致模型即使输出语音标签也在落库前被降级成文字。
- 外语角色只要模型漏写中文翻译，旧逻辑就把语音标签降级成普通文字；最后兜底又只支持中文，无法恢复。
- “重新发语音”没有被自然语句识别器完整覆盖。
- 新逻辑把用户明确要求作为本轮强约束：覆盖自动语音频率，不因外语翻译缺失而改变消息类型；模型仍不合规时，将本轮真实模型正文合并为一条语音标签，不编造新台词。超过 300 字仍按安全上限截取，平时的自动语音频率规则不变。

## 发布与验收边界

- 根网页与私人 `PhoneWeb.bundle` 仅同步本轮四个共享语音函数及消息落库门禁；私人专属存档、云备份、智能家居、卡顿保护和原生桥逻辑没有被网页整文件覆盖。
- 回归必须覆盖截图原话“发语音，我文盲”、自然说法“重新发语音”、语音频率 0、英语正文缺少翻译、普通非明确请求仍遵守频率 0、超长语音仍被阻止，以及网页与私人函数一致。
- 还需运行两端 JavaScript 语法、完整 `tests/*.test.mjs`、包结构与版本逆向校验，并核对公开 North 的既有工作区改动没有进入本次提交和私人包。
- Windows 生成的是 Mac 待编译 Xcode 源码包，不是签名 IPA；未经过 Mac 编译签名和真实 iPhone 覆盖安装，不能称为真机已验证。
