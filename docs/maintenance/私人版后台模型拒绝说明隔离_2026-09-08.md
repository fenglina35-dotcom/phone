# 私人版后台模型拒绝说明隔离

## 范围和状态

用户明确限定本项仅私人版本，并确认即使原样输出开启，也不能将明确自称 AI 并解释安全政策的拒绝说明作为角色对白。北京时间气泡和快捷指令属于独立的两边共有任务，不因此改成私人专属。

本项为未发布的本地修改，未打包、推送、部署 Edge Function 或进行 iPhone 真机验证。当前线上 v1210 不因本地代码已通过测试而自动获得修复。发布时必须分开核验私人包和后台函数，并同步私人角色 profile 的新标记。不能仅更新私人网页资源就声称锁屏推送已修复。

## 已确认和未确认

截图原文以 I cannot fulfill this request 开始，并明确自称 helpful and harmless AI assistant，随后解释安全准则。使用完整原文调用修复前实际 roleMessage，原样开关的开、关两个分支均返回 kind=message。旧客户端 roleServerPushUnsafeBody 也未识别它。

旧后台 roleModelOutputLeak 主要检测内部分析、提示词和指令解析，没有覆盖这种拒绝声明；原样输出会在该检测之前直接返回正文。因此漏投递是已复现的代码问题。拒绝为何被模型触发尚未确认：没有本次模型请求、profile 快照或供应商日志，不能断言是用户当时发送了有关内容，也不能把人设、旧记忆或中转站策略中的任何一项当作已确认根因。没有新聊天不等于后台请求没有携带上下文。

## 定点修改

- 仅私人 app.js 的 roleServerAutomationConfig 增加 privateBackgroundModelErrorGuard=true。网页不发送该标记，不添加私人拒绝检测函数。
- 共享后台 roleMessage 仅在该标记严格为 true 时检测明确 AI 拒绝文字、message.refusal 或 content_filter/refusal 完成原因，在原样输出、动作选择、写入 outbox 和通知之前返回 private-model-refusal。未带标记的既有 profile 行为不变。
- 该错误在同一调用内直接返回，不换供应商或要求模型改写安全拒绝。后台任务对它按终止失败处理，保留 providerReason，不进入原有同任务重试。普通日程下次检查维持原有退避规则，不关闭角色主动消息功能。
- 私人收件端也在原样输出前检测，覆盖旧服务器已生成但尚未收取的行；不执行其附带功能标签，不入角色气泡。保留角色级错误码、发生时间和行 ID，持久化后确认收件，避免重复拉取；不保存新的完整拒绝文本副本。
- 私人后台状态显示模型拒绝原因及历史收件错误；不把错误伪装成角色回复，不修改已有聊天或删除已经显示过的旧消息。
- 不采用全局 isRefusal 更严过滤，不修改普通聊天、电话、线下对话、智能家居或网页原样输出开关。角色正常说不同意、不愿意、换话题，以及普通 AI 话题和引用，均有保留测试。
