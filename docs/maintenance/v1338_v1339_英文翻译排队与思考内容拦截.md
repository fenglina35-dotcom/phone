# v1338 网页英文翻译排队 / v1339 私人源码同步

## 问题与结论

用户截图里同时出现了两类问题：角色的 `<think>` 与英文推理过程被拆成普通微信气泡；同一轮连续英文气泡中，前几条能翻译，后几条集中显示“翻译暂时失败”。

这不是单一翻译故障。源码核对确认：

1. 微信原始输出模式会绕过最终的思考内容拦截，未闭合 `<think>` 以及没有标签的连续英文推理句可能进入气泡。
2. 每个英文气泡在渲染后独立启动翻译，多条气泡会同时调用副模型，容易撞到限流或临时网络错误。

## 修复

- 网页与私人内置源码统一增加思考内容清洗。闭合的 `think/analysis/reasoning` 区块只删除内部思考并保留最终回答；未闭合区块从标签开始丢弃。
- 原始输出模式也执行思考泄漏检查。截图中“Storm is saying / So the context is / Let me think”等连续推理特征会进入一次纠正；纠正后仍是推理内容则不生成气泡。
- 网页英文自动翻译改为全局串行队列，避免同一轮气泡并发冲击同一副模型。
- 仅对超时、网络、429、5xx 和空结果自动重试一次。鉴权、Key、余额与配置错误不重试，并显示对应的安全提示。
- 翻译输出预算按原文长度提高到 320～1000，减少带推理模型因预算不足而返回空结果的概率。
- 排队期间消息被编辑或删除时，任务会释放占用标记，不会让该消息永久无法重试。

## 边界

- 英文自动翻译功能当前属于网页版本；私人版本本轮只同步微信思考内容拦截与版本源文件，没有新增整套网页翻译界面。
- 翻译仍走角色当前路线的副模型配置，没有改为内置免费通道，也没有新增后台接口或数据库字段。
- 本轮版本：网页 `v1338`；私人内置源码 `v1339`。私人原生版本仍是 `1.0.400 (400)`、桥接协议 `41`，本轮不打包。

## 验收要求

- 单元测试覆盖闭合与未闭合思考标签、截图式无标签推理、普通英文句不误拦、翻译串行、429 有限重试、401 不重试、空结果有限重试和排队消息变更后的清理。
- 浏览器回归必须加载正式网页入口与私人内置入口：原始输出第一次返回未闭合思考流，第二次返回正常中文，最终只能看到正常中文气泡；网页三条翻译最大并发必须为 1。
- 发布前必须通过全量 Node 测试、核心聊天发布闸门、语法检查和差异检查。发布后等待 GitHub Pages 完成，并逐字节比对线上网页资源。
