# 液态玻璃：磨砂 ＋ 一条细高光（定稿做法，v1300 / 私人 v1301）

> 她看完 v1300 说「这次做的高光美化非常好，是我想要的效果」，并要求把做法写下来，
> 以后再要做玻璃直接照这个来，不要再来回调。
>
> 这一套现在用在【信息（iMessage）】页的气泡、按钮和输入框上。
> 以后微信、抖音或别的地方要同样的玻璃，照搬这一页，别重新发明。

## 一、先记住这条规矩（前后返工三次就是因为不知道它）

> **任何铺满整块形状的白，只要压在 `backdrop-filter` 下面，就一定会被糊成一片奶白雾。**
>
> 所以：要么白根本不存在于形状内部（剪成环／边缘渐晕），要么白不在模糊层下面。

三次返工的经过，别再走一遍：

| | 做法 | 她的反馈 | 为什么错 |
|---|---|---|---|
| 第一次 | 把里面那层的白渐变撤成 `transparent` | 「还是有明显的白雾，我没有看到任何变化」 | 白不在那一层。白是**描边层**铺满整块画的，里面那层的 blur 把它一起糊开了 |
| 第二次 | 一点白都不画，高光全靠 `brightness/saturate` 提亮背景 | 「你现在是完全是透明的状态」 | 深色壁纸上，近黑的背景乘 1.62 还是近黑，高光根本看不见 |
| **第三次（定稿）** | **白照画，但把描边层剪成一个真正的「环」** | 「非常好，是我想要的效果」 | 白只落在 0.75px 那一条上，中间是洞，底下磨砂的身子露得干干净净 |

## 二、分层（三条，缺一不可）

```
.imsg-b            ← 身子：半透明底色 + backdrop-filter:blur(…)      = 磨砂
   └ :before       ← 描边：剪成一个环 + 白渐变 + brightness/saturate  = 细高光
```

1. **身子在父元素自己身上**：半透明底色 ＋ `backdrop-filter: blur(14px) saturate(1.32)`。
   这就是「磨砂」。**父元素的 background 里一点白都不许有**（`rgba(255,255,255,…)` 一律禁止），
   否则白雾立刻回来。
2. **描边在 `:before` 上，剪成环**。子元素永远画在父元素上面，所以描边**压在磨砂之上**，
   谁都糊不到它。
3. **描边层自己带 `backdrop-filter: brightness(1.72) saturate(1.68)`，但绝对不许带 `blur`**。
   提亮＋提饱和把底下背景的颜色吸上来——背景暖它就暖、背景蓝它就蓝，这就是她要的
   「高光跟着背景变颜色，不是只有白色」。一旦带了 blur，既吸不到颜色，又会把白摊开。
   因为这一层已经被剪成一条 0.75px 的环，提亮只作用在那一条上，**不可能再糊出白雾**。

## 三、环怎么剪（气泡：不规则形状）

跑 `python3 scripts/glass_ring_polygon.py`，把打印出来的四条 `clip-path` 贴回三个壳子。
`--check` 参数可以核对壳子里的 CSS 是不是这个脚本生成的（有测试卡着，见第六节）。

原理，一句话：

```
外圈正着走一圈 → 回到起点 → 桥到内圈起点 → 内圈【倒着】走一圈 → 回到内圈起点
```

- 内圈方向和外圈**相反**，nonzero 规则下就是一个洞。
- 两条桥（外圈起点 ↔ 内圈起点）完全重合，面积相互抵消，**看不见**。
- 点数一定是 `外圈 n × 2 + 2`。对不上就说明环豁口了。
- **刻意不用 `polygon(evenodd, …)`**：虽然也能挖洞，但要依赖 fill-rule 的支持；
  反向内圈用默认的 nonzero 就够，更稳。

尺寸常量都在脚本顶上：

| 常量 | 现值 | 含义 |
|---|---|---|
| `R` | 18 | 圆角 |
| `TW` | 7 | 尾巴那一条的宽度（气泡身子的左边缘） |
| `TH` | 10 | 尾巴高。她说过「尾巴太粗了，想改瘦一点小一点」 |
| `INSET` | **0.75** | 描边有多细。**她认可的就是这个值**，别再往粗了改 |

气泡和尾巴是**一整块**剪出来的（不是气泡一块、尾巴再贴一块），所以换了背景也不会露
拼接缝。验证办法：拿横条纹当背景，8 倍放大看尾巴根部——有缝的话条纹会错位。

## 四、环怎么剪（按钮／输入框：圆角矩形）

圆角矩形用不了多边形，改用 padding + 遮罩挖空，一样是环：

```css
.imsg-rb:before,.imsg-name:before,.imsg-plus:before,.imsg-send:before,.imsg-field:before{
  content:'';position:absolute;inset:0;border-radius:inherit;pointer-events:none;
  background:linear-gradient(140deg,rgba(255,255,255,.88),…);
  padding:.8px;box-sizing:border-box;
  -webkit-mask:linear-gradient(#000 0 0) content-box,linear-gradient(#000 0 0);
  -webkit-mask-composite:xor;
  mask:linear-gradient(#000 0 0) content-box,linear-gradient(#000 0 0);
  mask-composite:exclude;
}
```

`padding` 就是描边粗细，**不许超过 1.2px**。`box-sizing:border-box` 不能漏，
不然 `inset:0` 配 padding 会把伪元素撑大。

## 五、现在在用的数值

| 位置 | 身子 | 描边 |
|---|---|---|
| 对方气泡（换了背景） | `rgba(44,46,54,.52)` + `blur(14px) saturate(1.32)` | 白渐变 `.8→.72` + `brightness(1.72) saturate(1.68)` |
| 自己气泡（换了背景） | `linear-gradient(142deg,rgba(10,132,255,.84),…)` + 同上 | 同上 |
| 按钮（换了背景） | `rgba(58,60,70,.46)` + 同上 | 同上 |
| 输入框（换了背景） | `rgba(50,52,60,.42)` + 同上 | 白渐变 `.5→.44` + `brightness(1.34) saturate(1.3)` |
| 没换背景 | 不透明底色 `#26262a` / `#0a84ff` + 同样的 blur | 白渐变 `.72→.64` |

**输入框那一圈必须单独调轻**（白更淡、提亮更小）。她说过
「输入框两边白色的晕染太多，上面的字都看不清，那个小话筒也看不清」。

白渐变统一用 `140deg`，从亮到暗再到亮——这样高光才「有虚有实」，
不是一圈死白的包边（她最早的原话是「为什么会有这种很明显的分界线包边」）。

**发出去的图片不套这一套**：`.imsg-b.pic` 把 `clip-path`、`background`、`box-shadow`
全部 `none!important`，`:before` 直接 `display:none`。她要的是原模原样的图片，
一点包边都不要。

## 六、卡着这套做法的测试

改玻璃的时候这些会先红，别绕过去：

- `tests/phone-imessage-glass.test.mjs`
  - 「高光是沿着轮廓描的一条细线」——环的点数必须是 `外圈×2+2`、两条桥必须完全重合、
    环宽在 0.6–1.3px、按钮那圈必须真挖空且 padding ≤ 1.2px
  - 「白雾的根在描边层：白必须被剪成一个环，不能铺满整块」
  - 「气泡和按钮里面不再蒙一层白雾，只有磨砂」——身子那一层一点白都不许画，且必须有 blur
  - 「高光跟着背景变颜色」——描边层必须有 `brightness+saturate`、必须**没有** blur
  - 「输入框那圈单独调轻」——白和提亮都要比别处小
- `tests/glass-ring-recipe.test.mjs`——壳子里的 `clip-path` 必须是
  `scripts/glass_ring_polygon.py` 生成的（防止有人手改数值、脚本和实现对不上）
- `tests/permanent-fix-guard.test.mjs`——三个壳子里的环和提亮标记都登记在册

浏览器实测在 `scratchpad` 的 `imsg.cjs` 里，有六项专门盯这套分层
（磨砂在身子上、描边不糊、描边还有白渐变、身子一点白都没有、浏览器真把描边剪成了环、
按钮那圈是挖空的细边）。
