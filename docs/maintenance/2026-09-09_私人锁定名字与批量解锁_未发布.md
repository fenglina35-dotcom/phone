# 私人锁定名字与批量解锁修复

2026-09-09。用户授权先修复，不打包、不提交、不推送、不部署。当前工作区还有其他任务的未提交修改，均保留。本记录不代表手机已安装或线上已生效。

## 范围与原因

- 私人版：系统屏蔽页显示角色名字的代码及扩展存在于已核验 v1214 源码 ZIP，并非漏打包。前端命令未携带 by，原生本机命令固定 by:nil；仅 role-app-watch 才保存角色名字。导致角色普通锁定缺少显示来源。用户设备具体触发路径未取得日志，已确认的是代码缺口。
- 私人版：原生管理页一次批量解除锁定，recordExplicitManualUnlock 却按 token 产生多个事件。后台和本地的旧固定回退文案与截图中的逐 App 报名一致；截图不能证明每句都走了回退。

## 改动与保护

1. 私人 PhoneWeb.bundle/app.js 在实际命令中明确 role/owner；PhoneNativeBridge 转交 by；CompanionSyncView 对 role 及 role-app-watch 保存角色名，对明确 owner 清除旧角色归属。未知旧来源不推测归属。仍按稳定 App ID 保存，24 字截断、共享容器同步、锁定权限检查、失败回滚及解锁清理不变。
2. 原生管理页的批量按钮显式 batch:true，单项调用保持默认 false。一次批量操作只创建一个 UUID 的 manualUnlock 事件，source 为 native-management-batch；真实目标 ID 保留为数组，给角色的 appName 为整体描述，不包含名单。空集合无事件，旧事件不删除、不靠时间相近合并。仅代表本次批量解除的锁定，不宣称取消每日限额等其他屏蔽。
3. 本地与 phone-role-push 根据明确批量来源提示角色只自然回应一次，不报名字。原文开关两态覆盖；后台批量生成范围为一条，不改变普通消息数量设置。正常回复来自模型；批量生成失败或无效时保留错误，不套用单项固定回退。单项提醒原有行为不扩大修改。
4. 公开网页、公开 North 原生及公开能力开关未由本次修改；后台批量事实仅在私人项目读取。智能家居、睡眠电量算法、限制权限、模型线路与密钥不变。
