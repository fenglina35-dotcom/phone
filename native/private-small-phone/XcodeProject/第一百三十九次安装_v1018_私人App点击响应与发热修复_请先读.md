- 原生桥：25

## 安装前

1. 必须完整解压本次 ZIP，不要在压缩包内直接打开工程。
2. 使用全新的工程目录，不要覆盖 v1017 或更早版本。
3. 先读同目录的 `请在Mac编译前先读.md`，再打开 `PhoneCompanionTest.xcodeproj`。
4. Windows 自动测试不能代替 Mac 编译、签名和真实 iPhone 的温度、触摸与持久化验证。

## 本次确定原因与修复

- 本次没有把卡顿继续归到单一 CSS 或网络问题。v1009 已降低 iOS 玻璃合成层和原生写盘压力，但当前私人 App 点击后仍会在 JavaScript 主线程重复序列化整份微信、真实好友和群聊历史；滚动由 iOS 合成线程继续工作，所以会出现“滑动正常、点击和页面渲染不响应”。v1018 为大聊天归档加入有界结构指纹，归档未变化时直接复用已确认的本机引用；私人 App 的普通保存延后到空闲时执行，同时退出前和显式删除仍走原有强制持久化链路。
- `pageshow`、恢复可见和窗口聚焦原来会各自强制刷新伴生数据与后台角色收件箱，短时间内可能重复唤醒原生桥和网络。v1018 合并为单一防抖恢复入口，最终仍分别执行真实伴生快照和后台消息补拉。
- 好友请求与拦截电话维护循环由每秒改为每五秒，并在页面隐藏时停止；到期事件、重试次数和真实状态规则不变。
- 私人 App 的屏幕共享协调器原来即使未共享也每 0.5 秒在主线程轮询；现在未启用时每 4 秒轻量检查，启用共享后恢复 0.5 秒帧轮询。屏幕时间 `DeviceActivityReport` 不再全天挂在 WKWebView 下方，只在真实读取请求发生后的短窗口挂载。
- 网页源码与私人 App 内嵌网页同步性能修复；原有私人电话布局差异保留，没有整文件覆盖。

## 不得回退

- 朋友圈真实模型回复、后台通知及消息入聊、普通微信回复、真实伴生数据、通话和内外置语音隔离保持 v1017 稳定链路。
- 大聊天删除仍必须先刷新真实归档再报告成功；退出后台仍必须强制保存，禁止为了流畅牺牲消息持久化。
- 屏幕共享启用后仍须维持原有实时帧频；真实 Screen Time 读取必须能临时启动 Report 扩展。
- 不修改用户外置语音的 base、key、model、voice；不修改 iPhone 底部系统区域。

## 真机必测

1. 冷启动后在首页连续进入微信、朋友圈、设置、小事簿和情侣空间，确认点击能及时进入，不出现半屏停住；持续使用至少十分钟，观察手机温度。
2. 在较长的角色聊天里连续发送、返回、再次进入并重启 App，确认最新消息和删除结果没有丢失。
3. 把 App 退到后台再返回，确认后台角色消息仍能补入聊天页且不重复；伴生数据仍能刷新。
4. 发起一次真实屏幕时间读取，确认读取期间 Report 扩展能返回数据；读取结束后普通点击恢复平稳。
5. 发起一次远程屏幕共享，确认启用后画面和真实角色字幕链路没有因空闲轮询降频失效。
6. 冒烟复测普通微信、朋友圈、后台通知、通话、内置／外置语音、共同相册和小事簿。
