# 第一百九十三次安装：v1069 私人 App WebContent 恢复与内存边界

本次版本：

- 网页核心：v1069
- 私人 iOS：1.0.193（构建 193）
- 原生桥：25

## 本次只改私人 App 稳定性

1. 存储占用明细在私人 App 中不再遍历并反序列化全部 IndexedDB 媒体，只读取安全概要和原生容量估算。
2. 私人 App 的图片 JavaScript 内存缓存增加软上限；只释放可重新从本地存储读取的非可见副本，不删除真实图片、聊天或用户存档。
3. WebContent 第一次终止后等待 5 秒，并重新打开本安装包内唯一的 `PhoneWeb.bundle/index.html`。
4. 两分钟内第二次终止会停止自动重载并显示失败页，避免白屏、屏保和重载循环继续升温。
5. 网页核心仍为 v1069；公开网页不走上述私人 App 分支。

## Mac 安装

1. 把整个 ZIP 复制到 Mac 后完整解压到全新目录，不要直接在压缩包里打开，也不要覆盖旧工程。
2. 打开 `PhoneCompanionTest.xcodeproj`，选择自己的 Team 和真实 iPhone。
3. 执行 Product → Clean Build Folder，再编译运行。
4. 覆盖安装后先打开版本页，必须显示 `v1069 / 1.0.193 / 原生桥 25`；若仍显示 1.0.192，说明手机运行的还是旧包。
5. 不要删除旧 App，除非已经确认数据备份；覆盖安装才能保留原手机数据用于这次复现。

## 真机验收顺序

1. 连续点击、打开和返回多个软件，观察触摸响应和温度至少 15 分钟。
2. 打开一次“存储占用明细”，确认不会因为计算 1.68GB 图片占用而卡死或持续发热。
3. 若 WebContent 终止，只应等待后恢复一次；再次终止应停在失败页，不能反复白屏和跳回屏保。
4. 冒烟检查普通微信、朋友圈真实回复、后台通知入聊、真实电量／位置／健康／屏幕时间、通话、外置语音配置和共同相册。

Windows 已通过 1065／1065 自动测试，并确认根 `app.js` 与私人 `PhoneWeb.bundle/app.js` 一致。当前证据能确认旧版存在大值扫描、无界图片内存缓存和连续自动重载风险，但 Windows 不能证明 Mac 编译、签名或真实 iPhone 长期问题已经修好。本包必须完成上述真机验收后才能下最终结论。
