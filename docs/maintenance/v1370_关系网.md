# v1370（网页）关系网

仅网页；私人包仍是 v1369 / iOS 1.0.425（cohab-theater.js 已同步，靠 typeof 判断，私人版没有关系网时不生效）。

## 用户要求
给恋人建立和别人的关系：微信里的角色或捏出来的人物卡；两个人互相认识、知道是什么关系；能写过往、感情深度，角色和我都能调；角色能从自己的关系网推荐名片，我加了以后两边都知道是谁（他查我手机也认得），线下剧场不填也知道；推荐名片后自动立关系（默认开）；捏出来的人出现在他的微信好友里；每次只带相关的几个人；同一称谓不能重复、名字不能重复；已故/失联/没有微信不能推荐；生日纪念日会提；入口在朋友资料里；我自己是固定卡片。

## 数据
`S.relNet`：`people`（人物卡：姓名、年龄、性别、身份、性格、和我的关系、头像、状态、补充、生日、忌日/纪念日；转正后记 `cid`、`introducedBy`）、`links`（a、b、ab=b是a的、ba=a是b的、fa/fb 两边好感、conflict、how、story[]、pinned 常驻、locked、origin、pending、log[]）、`autoLink`、`detailCap`。
人物卡转正（被推荐名片加进微信）后关系里的 key 换成联系人 id；联系人被删时自动变回人物卡。

## 进提示词
`relPromptFor`：每次带一行名单（最多 30 人）；详细资料只带这次提到（名字/称谓/「你妈」）、在场、常驻、今天明天有生日纪念日的人，最多 detailCap（默认 6，1–10）。微信私聊、群聊（单独调用带 query，合并调用带每人名单 + gContext 在场成员关系）、线下约会 offlineSystem、共同生活 cohabSystem、剧场来客（cohab-theater）都接上。
他登录我微信时通讯录里标「这是你的妈妈（你推荐给North的）」（relLoginTag）。

## 规则
- 同一个人身上同一称谓只能一个（朋友/同事/同学等可重复）；名字不能和人物卡、联系人本名/备注、我的名字重复，否则保存不成功。
- 角色调好感 `[关系|名字|±n|原因]`：单次 ±10、一边一天 ±20、锁定不变、有记录；线下约会结束、剧场来客离开后角色回头看一次（只在提到相关人时调用模型）。
- 推荐名片：只能推关系网里状态正常、不在微信里的人；已故/失联/没有微信的推不出来。
- 我推荐名片给角色、角色 [已加] 后自动立关系（待确认）。
- 他的微信好友：关系网里的人出现，默认「妈妈」好友被顶替；查他手机同步来的「妈妈」聊天并进这个人，不会有两个妈妈；已故等不出现。
