# v1728 真人店铺走中转线路（根治「真人店铺连接失败」）

她要求先根治云端的问题：授权失败、服务器暂不可用、美团（真人店铺）经常刷不出来。

## 原因

- 真人店铺的所有接口（`north_market_*`）、店铺图片显示、图片上传，都直连 `lkhlyfpssmrjkkzhuzag.supabase.co`。
  国内很多网络到 supabase.co 会被重置（以前 vivo/OPPO 实测 ERR_CONNECTION_RESET），所以经常刷不出来。
- 真人好友早就有自动选线：`pfTransportRoute` 同时试直连和 `license.smallphoneapp.com` 中转，谁先通走谁。
  但中转 Worker 只放行好友接口，店铺没接进来。
- 授权本来就是直连加中转两条线，两条都不通才报「暂时不可用」。

## 改法

**中转 Worker**（`services/phone-license-relay/worker.mjs`，需要在她的 Cloudflare 部署）
- `/rest/v1/rpc/` 白名单增加小手机客户端实际调用的 `north_market_*` 接口。
  不含管理员加款、触发器、内部函数（admin_credit、*_trigger、identity、storage_owner、auto_deliver、split_expire）。
  原样转发 apikey、Authorization 和请求正文，鉴权、店主、余额校验仍由原数据库函数完成；只发一次，不自动重试。
- `GET /market-media/<店主md5>/<文件>.jpg`：只读公开桶 `north-market`，只返回图片，可缓存 7 天。路径严格校验，拒绝 `..` 和查询参数。
- `POST /market-upload/<路径>`：只收 jpeg/png/webp/gif，≤1MiB，原样转发 `x-north-phone`、`x-north-secret`，写入原桶，桶策略照旧校验店主目录。
- `GET /market-ready`：返回 `market-relay-v1`，不碰数据库。客户端靠它判断中转是否已支持店铺。

**客户端**（`commerce-ui.js`，网页和私人两份相同）
- `northMarketBase()`：复用好友的选线结果。选中中转、并且 `/market-ready` 确认支持时走中转，否则直连。
  所以先上线网页、后部署 Worker 也不会把店铺弄坏。
- 只读接口网络失败时换另一条线再试一次；写操作（下单、付款、发布等）一律不重发。
- 店铺图片：`northMarketImage` 仍只认原始地址，确认安全后，走中转的人显示时换成 `/market-media/` 地址。
  保存到数据库时把中转地址换回原始地址，数据库里始终是原始地址。
- 上传图片走 `northMarketUploadUrl(path)`。
