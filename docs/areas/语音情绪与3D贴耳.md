# 语音情绪与 3D 贴耳（设置 → 声音与通话 →「细腻情绪与 3D 贴耳（新）」）

## 现在是怎么工作的

- 一个开关：`S.settings.voiceExpressive`，默认关。关掉时所有入口都走原来的逻辑（`ttsPerformanceText` 里的旧语气映射）。
- 模块：`voice-expressive.js`（网页与私人包同一份），数据：`binaural-hrir.js`（KU100 近场 HRIR，0.25m/0.5m，16 位，CC BY 4.0，按需加载）。
- `app.js` 只有几处带 `typeof NorthVoiceExpressive` 保护的调用：
  - `ttsPerformanceText`：开关开、模型是 Fish S2/S2.1 或 ElevenLabs v3 时由 `NorthVoiceExpressive.performance` 生成念法，返回 `null` 就走旧逻辑；
  - 微信语音回复与短信语音创建处：`split()` 把正文里的中文小提示和方位标签拿出来，`m.content` 是干净文字，`m.voicePerf` 是带提示的念法，`m.voiceSpatial` 是方位标签（记在第几个字）；
  - `warmVoiceMsg`：`handPerf(m.content,m.voicePerf)` 一次性交接念法，发声仍是 `ttsArr(m.content,…)`（语言锁照常）；合成后 `binaural()` 渲染成双耳 WAV，失败就用原音频；
  - `buildSystem`：`prompt(c)` 追加小提示与方位的用法说明（只在开关开时）。
- 3D 只处理语音条，不处理实时通话。

## 踩过的坑

- 旧做法让声音僵硬、跑偏：整条语音一个语气、固定英文标签塞句首；轻笑/叹气会硬加「[laughing] 哈哈。」「[sighing] 唉。」；强标签（angry、excited、shouting、sobbing）会把 Fish 的参考音色拉偏。新做法只用温和标签、限量（一条最多两个、出声的最多一个、同一角色 6 分钟一次），不再硬加笑声叹气。
- `app.js` 的 `S` 是脚本级 `let`，不在 `window` 上；模块要直接按名字读 `S`（测试里专门锁了这一点）。
- 好几条老测试锁着 `await ttsArr(m.content,o,{cue:m.voiceCue})` 和短信语音的原写法，新逻辑只能挂在后面，不能改这些行。
- 私人包目录默认被 `native/private-small-phone/.gitignore` 忽略，新文件要加白名单，否则进不了提交和安装包；私人入口清单 `private-phone-web.manifest.json` 也要登记。

- 只在创建消息时拆标签不够：用户手机上出现过正文仍带 [左耳][轻笑] 的语音（原因未能在设备上确认）。现在 `normalize()` 在气泡渲染和 `warmVoiceMsg` 里都会再拆一次，并显示「3D」小标记表示这条确实渲染了双耳。
- 用户明确要求（笑一笑、凶一点、撒娇）存在 `m.voiceAsk`，经 `handPerf` 交给 `performance`，这一条一定带对应标签，不受限量和冷却。

- 第三版（v1748/私人v1753）：只靠角色顺手写的提示，标签又是自编描述，Fish 不一定认，笑声短得听不到。现在合成前多一步「语音导演」`direct()`：副模型按导演规则（`DIRECTOR_PROMPT`，参考 ttsdirectorskill-chatting 的实测结论，自写，未复制原文）给台词加语气词和 Fish s2.1 上稳定的标签，中英文都支持；`directorValid()` 防止改动台词；结果缓存在 `m.voiceDirected`。语音字数用 `ttsSpokenLength()`，标签不占额度。

## 试过但失败的办法

- 每条语音只配一个整体语气 + 固定标签 + 硬加拟声词（v1744 之前的默认做法，开关关着时仍是它）：用户反馈机械、笑太勤、叹气不合时宜、声音会变尖变低。

守住它的测试：`tests/voice-expressive-v1744.test.mjs`。真实 Fish 音色的听感只能由用户试听判断。
