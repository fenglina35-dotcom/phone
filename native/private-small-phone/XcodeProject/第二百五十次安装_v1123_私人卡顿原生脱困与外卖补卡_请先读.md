# 第二百五十次安装：v1123 私人卡顿原生脱困与外卖补卡版

## 安装前先保护数据

1. 不要卸载手机里现有的“小手机”，不要清缓存，也不要退出手机号。
2. 必须使用相同 Bundle ID 覆盖安装；先卸载会删除 App 容器和仍可恢复的本机候选存档。
3. 把本次 ZIP 解压到全新文件夹，再用 Xcode 打开；不要把文件复制进任何旧工程。
4. 当前若正在严重发热，先彻底退出小手机并让 iPhone 降温，再覆盖安装。

## 本次私人 App 更新

- 性能改动仅进入私人 iOS 宿主和私人 `PhoneWeb.bundle`，公开网站不随本包发布。
- WebContent 连续六秒无响应、重复终止或严重发热时，由 WKWebView 外的原生面板接管并阻止页面继续自动重载；这项保护的真机效果仍须覆盖安装后验证。
- App 退到后台会停止响应探针，回到前台才恢复；严重／临界发热或离开前台时，自动与手动重开都会被阻止。
- 用户明确选择重开后，先给当前页面最多八秒完成存档；结束时再次核对前台和温度，条件不安全就取消重开。代码不会主动删除已落盘的聊天、角色、图片、登录信息或密钥，但页面彻底卡死时最后尚未落盘的变化不能绝对保证。
- 玻璃主题内置图标和第二页照片只改为异步解码，不启用可能造成图片迟迟空白的 `lazy`；矢量备用图标始终保留，图片失败时点击位不会变成空白。
- 保留 v1123 的本机候选安全合并：完整资料取选中的基底，其他物理副本只追加同角色 ID 的微信与通话，真人好友和真人群聊保留当前本机内容。
- 私人包同步包含真实外卖订单到达“支付宝 + 确认支付”官方中间页后的订单卡片补建；朋友电脑端浏览器服务需安装本次另附的 0.1.4 新代理安装包。

## 在 Mac 上编译安装

1. 打开 `PhoneCompanionTest.xcodeproj`。
2. 为主 App 和所有扩展选择同一个开发者团队，并选择真实 iPhone。
3. 直接运行并覆盖现有 App，不要先卸载。

## 安装后第一轮验收

1. 确认页面核心为 v1123、私人 iOS 为 1.0.250（250）、原生桥为 25。
2. 冷启动后先停留两分钟，检查点击延迟、温度、图片和图标；再退后台一分钟并回前台，确认没有后台探针或白屏重载循环。
3. 若原生面板出现，先选“继续等待，不重开”；手机降温后再测试“安全重新打开小手机”。
4. 数据仍不完整时，选“重开后检查本机存档”。在候选列表中使用“以这份为主，安全合并全部角色聊天”，先看去重后结果再确认；不要使用“整份恢复”覆盖当前布局。
5. 核对普通角色聊天、通话、真人好友、真人群聊、头像、图片、朋友圈、主题、组件、后台通知和普通回复。
6. 在确认数据正确前不要建立新的覆盖式云备份；如合并结果不对，使用“撤回上次本机恢复”。

## 验证边界

Windows 已能验证 JavaScript 语法、自动测试、版本链与 ZIP 逐文件一致性，但不能替代 Mac 编译、签名和真实 iPhone 长时间验证。朋友电脑真实订单也仍须实际走到支付宝确认页，确认聊天补出订单卡片；自动测试通过不代表这两项真机闭环已经完成。
