# v1656 角色点外卖规格修正

现象：角色给用户点真人店外卖时，不用选规格的商品能成功；有尺寸、甜度、温度等规格的商品，常常提示「外卖暂时没有下单成功：商品或规格方案未通过校验」。查完店铺后，有时还直接提示「查询后的角色模型请求失败（500）」。

原因：
- 选规格那一步，模型给的方案只要差一点（写了选项名而不是 ID、漏了必选组、单选组选了两个、编了不存在的组、JSON 前后多说了话），旧代码都会整单拒绝。
- 「四寸」这类尺寸词被当成商品名必须包含的词，可商品名里没有「四寸」，于是判成口味不符。
- 用户要求的规格，在这个商品上根本没有对应的规格组时，也被判失败。
- 查店铺后的那次回复，中途夹着系统消息。有的中转接口会报 5xx，失败后没有重试。

修复（commerce-ui.js，网页和私人包相同）：
- `northRoleRepairSelections` / `northRoleRepairChoice`：按真实菜单修正模型给的规格。
  - 选项名能换成对应 ID；不存在的组和选项直接丢掉。
  - 单选组只留一个；必选组没选的，用默认选项（没有默认就用最便宜的）补上。
  - 用户明确要求的温度、尺寸、甜度，会选上对应的真实选项。
- `northRoleMoveSpecWords`：尺寸、甜度、温度、辣度这类词从「必含词」挪到规格偏好里。
- 用户要求的规格在这个商品上没有对应的规格组时，不再判失败。规格组有、但没有对得上的选项，仍然拒绝，比如要热的、店里只有冰的。
- `northRoleModelJSON`：模型在 JSON 前后多说了话，也能取出 JSON。
- 方案没通过核对时，把具体原因告诉模型，让它再选一次。仍然在 3 次模型调用预算内。
- 失败提示改成显示具体原因，不再只有笼统的「商品或规格方案未通过校验」。

修复（app.js，网页和私人包相同）：
- `northShopFlatMessages`：查店铺后的回复第一次失败（不是用户取消）时，把中途的系统消息改成普通消息、合并相邻同角色消息，再请求一次。

不变：
- 云端报价和付款前的核验照旧。
- 商品本身不符合要求（比如要草莓却选了巧克力）仍然拒绝。
- 没有付款就不会显示成功。

私人包只同步代码，没有升版本号，也没有打包。
