# 第一百三十次安装：v1009 私人 App 点击渲染与发热修复

版本核对：网页 v1009；私人 iOS 1.0.130 (130)；原生桥 25。

请完整解压 `SmallPhone_v1009_NativeRenderThermalRepair.zip` 到一个全新目录。不要覆盖 v1008 或任何旧工程，也不要把旧工程中的 `PhoneWeb.bundle`、Swift 文件或配置复制进来。

在 Mac 上打开 `PhoneCompanionTest.xcodeproj`，选择 `PhoneCompanionTest` Scheme 和真实 iPhone，先执行 `Product → Clean Build Folder`，再编译安装。若设置页版本不是 v1009／1.0.130 (130)，立即停止，说明打开的不是本次全新工程。

本次针对“左右滑动正常，但点击 App、打开组件或页面重绘会冻结，手机很快发烫”的根因修复：

1. 私人 App 的大容量存档读取、校验、备份和原子写盘移到串行 utility 队列，只有 WKWebView 回执回到主线程；点击后不再在 iOS 主线程同步处理整份存档。
2. 网页与原生桥改用单个 `stateJSON` 字符串传输核心存档，兼容读取旧版原生存档；聊天、朋友圈、账号和已有恢复副本不清空、不重建。
3. 私人 App 启动时不再把全部历史照片展开进 JS 内存，只缓存主屏和联系人等关键图片，其余照片在真正显示到当前页面时再从本机图片库读取。
4. 图片垃圾回收认识未展开的 `idb:` 引用；手动完整备份和美化包导出仍会在副本中补齐图片，不能因为懒加载删除或漏导历史照片。
5. 恢复快照先检查五分钟节流再解析大 JSON；启动时不再强制重复写核心存档，也不再在 9 秒后执行整库通用云备份。私人账号自己的延迟云备份继续保留。

真机请按顺序验收：

1. 安装后先静置 60 秒，观察机身是否仍在没有操作时持续升温。
2. 连续点击主屏 12 个不同 App／组件并返回，每个入口都应能打开；不能再出现只渲染半屏、按钮完全点不动或点后长时间冻结。
3. 在微信连续发送三条消息、进入朋友圈、共同相册、设置和情侣空间，确认文字、头像及历史照片都能逐页显示，已有聊天和相册数据没有丢失。
4. 修改一项设置并完全关闭、重新打开 App，确认改动仍保存；再检查“隐私、查岗与数据”里的存储状态没有报错。
5. 手动执行一次完整导出／云备份，确认导出仍包含历史图片；自动备份不得在刚启动或持续点击期间争用前台。
6. 普通微信回复、朋友圈评论、电话、后台通知分别做一次冒烟，确认 v1008 已修复功能没有回归。

Windows 自动回归不能替代本次 Mac 编译、签名和真实 iPhone 温度／点击验收。若仍卡，请保留卡住前最后点击的入口、等待秒数和当时机身温度，不要清数据或卸载后再复现。
