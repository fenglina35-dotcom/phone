# 第二百四十九次安装：v1123 / 私人 iOS 1.0.249（249）

## 先保护现有数据

1. 不要卸载当前“小手机”App，不要清理页面缓存，也不要退出手机号。
2. 本包必须使用同一个 Bundle ID 覆盖安装；覆盖安装会保留 App 容器，卸载会删除容器。
3. 解压到全新文件夹后再用 Xcode 打开，不要把文件混进旧工程。

## 本次可见更新

- 设置页测试结果会明确写出路线、主／副槽位和模型名，并保留上游返回的 503 原因（密钥会隐藏）。
- 每个角色的微信设置新增“模型与路线诊断”，显示该角色最近一次真实请求所用路线、主／副模型、模型名、请求规模、HTTP 状态和上游原因。
- 角色已经选择副模型时只请求这一份副模型；没有第二个副模型，也不会虚构一次回退。只有角色原本选择主模型且同路线副模型已配置时，主模型失败才允许回退一次。
- 私人完整页面与公开网页核心同步为 v1123；私人 iOS 升为 1.0.249（249），原生桥仍为 25。
- 没有删除或迁移聊天、图片、角色、密钥、云备份、本机存档和既有设置。

## 在 Mac 上编译安装

1. 打开 `PhoneCompanionTest.xcodeproj`。
2. 为主 App 和所有扩展选择同一个开发者团队，选择真实 iPhone。
3. 直接运行并覆盖手机上现有 App；不要先卸载。

## 验收

1. 在设置里分别点击“测试主模型”和“测试副模型”，确认结果写明实际测试槽位和模型名。
2. 让两个使用同路线、同副模型的角色各真实回复一次，再分别进入角色微信设置的“模型与路线诊断”。
3. 对比两者的路线、实际模型、请求条数／字符数、HTTP 状态和上游原始原因。只有这些数据相同且同一时刻稳定复现，才能继续判断为客户端问题。
4. 同时检查现有聊天、头像、图片、云备份入口和私人 App 身份识别仍正常。

## 验证边界

Windows 侧可以验证源码语法、自动测试、网页／私人 Bundle 同步和 ZIP 逐文件完整性；不能代替 Mac 编译、签名、真实 iPhone 安装，也不能替上游模型服务证明 503 已消失。
