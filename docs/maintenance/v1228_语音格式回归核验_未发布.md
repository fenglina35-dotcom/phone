# v1228 语音格式回归核验

2026-09-09。用户反馈明确要求语音和角色主动语音均可能变成纯英文文字，并要求仔细对比 9 月 5 日版本。当前为网页与私人内置网页共同的本地候选 v1228；未提交、未打包、未推送。私人原生版本仍为此前的 iOS350、桥37，本轮不改原生工程。公开 North、智能家居与空调现场不动。

## 历史证据与根因

以 2026-09-05 23:03:04 +0800 的 `90accb87`（v1181，当天最后一次提交）对比本轮起点 `e0852c94`。`parseVoiceTagLine`、`ttsContentLang`、`voiceEnglishPrompt`、`ttsArr` 函数相同，未发现语音接口或语言设置被替换。两版都无法识别无逗号的“先生你发句语音”；旧版也会把缺翻译的外语语音降成文字。因此不能声称整版回退必能解决，或所有问题都是最近改动引入。

本轮基线使用真实网页和私人 aiReply、消息存储与气泡渲染，仅模型 HTTP 和音频预热为隔离夹具。已复现：无逗号请求在自动语音频率为0时落成文字；原样输出跳过语音纠正，缺翻译标签直接变成英文文字。另发现提示词中的英文语音示例缺中文翻译，且隐藏的“语气:温柔”被纯英文检测误当成中文正文。

## 改动及影响面

| 位置 | 本轮变化 | 非回归边界 |
| --- | --- | --- |
| 明确语音请求识别 | 覆盖先生等常见称呼后不带逗号的请求 | 否定、用户自述已发语音不作为新请求 |
| aiReply 语音格式处理 | 明确及自主语音共用一次有界纠正，覆盖原样开关两态 | 合规语音和普通中文不增加模型调用；自动频率0仍不主动发语音 |
| chatResultText | 仅 aiReply 明确指定的语音候选允许进入后续格式修复 | 其他聊天、电话、后台等消费者仍执行原来的即时英文检查；最终校验前不作为消息发布 |
| 英文检测 | 去除语音末尾隐藏语气后检查正文/译文 | 有真实中文译文的外语语音保留；心情及功能元数据不当作翻译 |
| 最终消息 | 修复成功才按语音发送；失败明确报错并留拦截诊断 | 不伪造译文，不将未翻译英文降级为文字，不改 base/key/model/voice |
| 两端与共享状态 | 仅同步目标函数，私人传本轮自身诊断上下文 | 不把网页 app.js 整份覆盖私人；账号切换检查、历史、权限、通知及TTS接口保持 |

纠正沿当前已有纠正模型配置，至多增加一次模型请求，可能产生相应调用费用。模型持续拒绝、空响应或无法给出正确语音格式时不会伪造成功。测试中只证明语音气泡与预热调度，不代表实际声音已播放。
