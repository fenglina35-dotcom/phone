# 角色扮演

角色扮演复用单次约会的显示组件，不复用现实约会状态。入口 `rpOpen`、`rpSaveSetup`、`rpCreateInviteFromAI`；数据仍在 `S.roleplay`，旧摘要保留。本局日期和虚构身份保持独立。共同生活剧场会读取现实关系、在场状态和生活联动，所以保留原角色扮演的多人房间，不将其整体搬入。

## 页面和输出

`renderRP` 和 `renderOff` 共用 `renderDateScene`，使用共同生活原有的 `offstage`、`offmsg`、`offbubble`、`offnar` 和 `offRevealText`。不再给消息附加旧 `rpmsg`、`rpbubble`、`rpnar` 样式类，避免旧角色扮演样式覆盖原气泡。`rpThemeContact` 复用约会外观生成函数，但外观存于剧情数据，不修改约会配色。模型与路线由 `rpReplySettings`、`rpRequestOptions` 独立配置；初次沿用旧副模型设置，之后以剧情设置为准。

按用户最新要求，角色扮演直接复用共同生活的 `offlineFormatPin` 和实际生效的 `modelUnfilteredOfflineItems`，原文输出参数也一致；非原文分支调用原 `offReplyItems`。`rpReplyItems` 仅在原解析结果上附加参演角色 ID、去掉已识别的姓名前缀，不再自己拆括号、判断动作、切引号或过滤正文。单人直接输出台词；多人只在台词行加姓名，旁白仍单独成行。角色邀请生成的 opening 字符串也采用同一个格式提示。不得为了角色扮演去改共同生活已稳定的解析实现，更不能调用其现实生活状态、查看手机或控制设备的副作用。

## 存档和记忆

`rpArchiveRecord` 先保存完整消息快照和基础摘要；结束时 `rpEnd` 等待 `saveNowAsync` 成功，再离开并异步调用 `rpSummarizeArchive`。模型失败或关闭页面不会使原文依赖总结结果。旧存档没有原文时明确说明，不能伪造补回。新开局的手动配置和角色邀请两个入口都保护旧内容。

`rpSyncArchive` 将“共同玩过虚构剧情”的记忆写入参演角色，使用 `summaryList` 隔离账号；不能把虚构身份写成现实关系。删除存档也删除对应记忆副本，重试总结不得让已删除记录复活。异步结果检查原状态、账号和记录仍存在。

验证：`tests/roleplay-open-v1384.test.mjs` 包含旧版必败的“模型仍等待时原文已保存”回归，以及双端页面、旁白分离、多人归属、编辑、滚动、失败原因和正常入口重载恢复。`tests/permanent-fix-guard.test.mjs` 保留三个功能标记。真实模型质量和真机效果以发布记录为准。

补充核对：`renderRP` 和 `renderOff` 现在调用同一个 `renderDateScene`，输入框共用 `off_in` 和原样式；回应按钮在“记下”正上方靠右，不能挤进输入栏。模型设置共用 `offModelSettingsHTML`，真实请求复用原诊断模块，使用 `rp:` 分区保留完整配置和请求结果。记录删除共用约会的按日期、一天前、三天前、全部删除界面；外观共用 `offAppearance`，原背景与五种颜色控件不省略。总结保留主副模型、整条与分段、重要度、编辑和重试。

结束后，先将完整剧情与消息触发标记一起落盘，再给本局有效参演角色调用 `scheduleReply`，回到微信承接刚玩的内容。提示明确区分虚构剧情与现实身份；重复结束不重复触发。保存失败、被拉黑和已删除的角色不发送。

## 可选的自然推进
剧情配置页的“允许角色自然推进剧情”按房间保存在 advancePlot，默认关闭，旧数据没有该字段也关闭。只有严格为 true 时 rpSystem 才追加自然推进规则，关闭时完整提示保持原样。规则要求先回应当前互动、发展已有线索、适量推进并留出参与空间，不每轮制造意外、不代替对方行动。临时配角的行动与原话保留在注明身份的原【旁白】中，避免归属为主角；已参演角色仍沿用原姓名及 cid，不新增联系人或改解析器。开关不触发定时请求，不改变手动“让TA回”与自动回应方式，不改历史剧情。

2026-11-02 副模型同行输出补修：截图证实模型会把多段【旁白】及带参演姓名的台词写在同一行，直接交给共用解析会将整段吞为旁白。rpReplyInputLines只在角色扮演入口为明确闭合【】和已参演姓名前缀补回换行，再调用原modelUnfilteredOfflineItems/offReplyItems；旁白中的引号、姓名及普通原文不重写，不调模型补格式、不改共同生活解析。与之前失败的offResponseParts整段先分类方案不同，此处先还原边界才调用原分类。临时配角仍按原旁白承载，未知姓名不自动变成参演人。原始请求输出诊断保留原文。

## 多存档、存档与总结分页（2026-11-03，ROLEPLAY_SAVE_SLOTS_V1）
用户要求像游戏一样一个角色有多局剧情；「存档就是存档，可以继续开局；总结就是总结」，两者分页看；长总结能收起；结束不重复总结；角色主动开新局要重新配置。按钮一个都不去掉（曾提议去掉「总结」被用户否定，见下）。
- 数据：正在玩的一局仍放在 `rpData(id)` 本身，原有聊天、总结、诊断函数不用改。暂停的局和结束的局整局（`rpSlotKeys()`：原文、本局设定、参演、summaryCursor、邀请卡 id、endNotified、saveId）收进 `d.saves`，结束的带 `ended:true`。记忆仍是 `d.memory` + 角色记忆总结，位置没变。
- 剧情存档窗口 `rpMemory(id,tab)`：「存档」页（`rpMemorySaves`）列没结束的（正在玩 / 已暂停：读取、删除）和已结束的（查看聊天、删除），以及旧版本结束时存在 `_end` 记录里的整局；底部「新开一局」。「总结」页（`rpMemorySummaries`）是记忆列表和总结模型设置，超过 90 字的总结默认收起（`rpSumToggle`）。顶上「存档」按钮和主页「剧情存档」默认打开「存档」页；编辑、删除、保存总结后回到「总结」页。
- 换局：`rpParkCurrent` 先用 `rpSaveProgressRecord` 只存 summaryCursor 之后的新内容（`_part_` 记录，和顶上「总结」同一套），再把整局移进 `d.saves`。`rpLoadSave` 读取，`rpNewGame` 打开带 `fresh:true` 的空白配置页；没有进行中也没有暂停的局时，`rpOpen` 和「配置开局」也是空白表单。回复进行中（busy）时不准换局、开新局。
- 结束 `rpEnd`：只把 summaryCursor 之后的新内容做成 `_end` 记录（没有新内容就不再记一条），推进 summaryCursor；微信承接只发一次（`endNotified` 按局记），收尾原文取整局最后 10 句；保存成功后 `rpParkEnded` 把整局移到「已结束」。
- 角色主动邀请 `rpCreateInviteFromAI`：有进行中的局时也重新设计一局，旧局先 `rpParkCurrent`。只有她正在那局页面里或那局正在回复时（`rpInviteKeepsCurrent`），才照旧发当前这局的卡，避免把她正在看的剧情换掉。
- `rpDeleteSave` 只删那一局聊天，并把它的微信邀请卡标成结束；记忆不动。删除联系人时 `clearContactRoleplayMemory` 同时清理各存档。
- 曾做过又撤掉：剧情页顶上的「换局」按钮（和「存档」页重复）。用户否定的提议：把「总结」并进「存档」、去掉「总结」按钮——她要两者分开。
验证：`tests/roleplay-save-slots.test.mjs`（双端真实页面：开第二局旧局完整保留、换局只存新内容、读取后气泡回来、删除不动记忆、顶上按钮、结束只存新内容并留整局聊天、两页分开、长总结收起展开、空白开局、角色邀请重新配置、她在页面里不打断）。`tests/roleplay-open-v1384.test.mjs` 相应改为从已结束存档读本局开关、从「总结」页看旧记忆。
