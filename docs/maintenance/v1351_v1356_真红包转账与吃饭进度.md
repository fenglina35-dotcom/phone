# 网页 v1351 / 私人 v1356 / iOS 1.0.422 (422)：真红包与转账、共同生活后主动消息、吃饭进度

## 现象

1. 在共同生活聊完后，角色发来的主动消息沿着更早的微信话题继续，和共同生活最新内容对不上，除非用户特意提起。
2. 红包和转账只有简单卡片，想要照真微信的五个页面：发红包页、红包卡片、点开后的「開」、领完变灰的卡片、转账键盘页。角色、真人好友、群聊都要同步。
3. 转账写的备注，卡片上不显示（角色其实看得到）。
4. 用户说过「吃过饭了」，后台主动消息又问「吃过饭了没有」。

## 原因

1. 主动消息的交接判断只在「用户刚发了一条微信」时生效；用户最后一句在共同生活里、角色主动开口时，没有交接提醒。
2. —
3. 卡片只写「你发起了一笔转账 / 请收款」，没有读备注。
4. 吃饭进度识别只认「吃完了 / 已经吃了 / 刚吃过」，不认「吃过饭了 / 吃过了 / 吃饱了 / 我吃了」，于是「用户已吃完」的提醒从没发出；后台拦截的问句也认不出「吃过饭了没有」。另外后台上下文超 8000 字时从开头截断，会把开头的状态说明一起截掉。

## 修复

- `roleReplyCrossChannelHandoff` 增加主动分支：最后的更新发生在共同生活或电话且用户在那里说过话时，主动消息必须从那一轮接着说；后台上下文 `roleServerPushRecentContext` 也带上这条交接提醒。
- 红包与转账：发红包页（`rpSend`）、转账键盘页（`tfSend`）、「開」弹层、领取详情页（`rpDetail`），领完卡片变灰并在聊天里留「你领取了…的红包 / …领取了你的红包」（只给用户看，不进提示词）。角色、真人好友私聊与群、AI 群的卡片共用一套；AI 群原本没有用户发红包/转账的入口，本轮仍只有领取。
- 红包卡片标题固定「恭喜发财，大吉大利」，祝福语写在第二行；领完写「已领取 · 祝福语」。转账卡片待收款时备注代替「请收款」，收完写「已收款 · 备注」。卡片文字位置照真微信往下放。
- 白天模式：发红包页、转账页、领取详情页跟着变浅。
- 吃饭进度：补齐常见说法，问句从句不算；本地与后台（`supabase/functions/phone-role-push`）都认得「吃过饭了没有」。后台上下文超长时先让最早的聊天让位。
