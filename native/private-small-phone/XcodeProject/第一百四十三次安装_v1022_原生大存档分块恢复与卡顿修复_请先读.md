# 第一百四十三次安装：v1022 原生大存档分块恢复与卡顿修复

## 本次版本

- 网页：v1022
- 私人 iOS：1.0.143（143）
- 原生桥：25
- 工程目录：`SmallPhone_v1022_ChunkedNativeCoreRestore`

## 为什么 v1021 没有产生真机差异

- v1021 只把整份大存档从巨型 JavaScript 源码改成了单个巨型 WebKit 参数。
- 存档正文虽然不再作为代码编译，但多 MB 字符串仍会在一次桥接中创建、复制和解码；真实存档足够大时，首页仍会只显示空壳，自定义图片为空、点击长延迟、温度上涨，启动完成后的后台收件也不会开始。
- 因此 v1021 并未真正拆除单次超大对象，本次不再继续调整图片重试或模型接口。

## 本次修复

- 原生存储后台队列读取并验证现有存档，存档格式与位置不变，不清空、不迁移、不伪造任何用户数据。
- 超过 128 KiB 的核心存档建立最长 90 秒的一次性读取会话；每次只向 WKWebView 传递最多 192 KiB 原始字节的 Base64 分块。
- 网页按顺序逐块读取并使用 `TextDecoder` 增量还原 UTF-8，确认字节数完整后才组装 JSON；完成或失败都会释放会话。
- 每一块都通过固定的小型 WebKit 函数和参数传递，不把分块正文编译成 JavaScript 源码。
- 启动完成前继续阻止伴生轮询、后台收件和好友同步抢占恢复；启动完成后立即补拉。

## 不得破坏

- 不得重写已经真机成功的朋友圈真实模型回复、后台主动通知、普通微信和消息落库链路。
