# v1238 备份等待与导入时序核验

日期：2026-09-12。基线为已上线的 v1237 / `a56a44e320e1a5fb7e56edf49e23bd4988652996`。本轮发布网页并同步私人内置公共源码；原生仍为 iOS355、桥37，不制作私人包。

## 被证据支持的结论

用户明确反馈：v1237 仍不能正常备份，且 iPhone 网页和安卓网页都受影响。不能继续把它归为华为 Edge 单一兼容性问题，也不能把前轮桌面大文件通过写成目标设备修复。

1. **v1237 引入了大量短字段导出的性能退化。** 分段序列化每累计很少的字段就无条件执行 `setTimeout(0)`。1000条聊天产生366次等待；实际10000条聊天、4327814字节，旧单体序列化18ms，v1237分段导出55905ms。定时器等待被字段数量放大。前轮约520 MiB测试主要是少量大图片字段，没有覆盖这个维度。
2. **文件导入缺少旧归档恢复完成的时序保护。** 页面可先显示，`_bootImagesPromise`仍在回填旧聊天；旧实现允许先应用新文件。延迟恢复的行为测试在旧实现失败，修复后等待旧恢复完成再应用。该竞争可以覆盖新导入状态，但尚无用户设备日志证明其就是所有导入失败的唯一原因。
3. **“页面ready”不能作为“归档恢复完成”的证据。** 本轮WebKit第一次重开测试读到空聊天，后续检查数据库仍有10000条；等待实际归档恢复后数据完整。这是测试读取时机错误，不是已确认磁盘数据丢失。
4. **截图大片空白仍未复现。** Edge/WebKit测试中存储卡高度约155/135px、图标14px，未发现相应几何异常。没有为了猜测此现象而修改全局玻璃样式。

## 验证结果

- 全量 Node：1820/1820通过；两个新增回归均先在未修实现失败。
- `check_backup_realistic_browser.cjs`：真实Edge和WebKit引擎，10000条聊天、48张不同图片、约7.3 MB，正常启动与持久化开启。导出约604ms和2563ms；导入并重开约1.3s和7.0s。确认导入成功提示，并等待实际归档恢复后，10000条和48张图片保留；两引擎页面错误为0。
- 导入阶段分解：Edge解析约259ms、应用773ms；WebKit解析约3819ms、应用2696ms。WebKit仍慢于Edge，但测试中计时器持续运行，不把桌面性能外推为手机性能。
- `check_large_backup_browser.cjs`：网页约520 MiB、私人内置源码约96 MiB，实际下载、全新存储文件导入、重开验证通过；美化兼容与损坏文件保护通过。
- `check_chat_authorized_phone.cjs`：网页和私人内置入口通过，包含已有授权、笔记、输出模式、真实构建提示词、可见回复、自动检查、忙状态释放、隔离与重载；仅HTTP模型为夹具。
- 三份维护DOCX仅追加，原正文及其他ZIP成员保持校验；环境缺少LibreOffice，未取得DOCX视觉渲染证据。

桌面WebKit不等于真实iPhone。本轮修复的是两个有回归依据的缺陷；真实手机全部卡顿、白屏原因尚未完全证实，不能宣称全部真机问题已解决。上线必须另核对Pages完成和实际线上资源字节。
