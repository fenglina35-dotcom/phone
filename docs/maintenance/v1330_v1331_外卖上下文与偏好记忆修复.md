# v1330 / v1331 / iOS399 外卖上下文与偏好记忆修复

## 事实与根因

- 淘宝闪购真实肯德基门店和 `【夜宵专享】吃堡堡4件套` 均能在已打开页面中看到，购物车仍为 0，说明失败发生在小手机动作交接层，不是门店页面关闭。
- 只说“想吃 KFC”时没有具体商品，旧代码仍尝试执行残缺动作，因而暴露“当前结构化动作没有可靠门店和商品依据”的内部提示。
- 下一句“随便点”或“四件套”只按当前气泡解析，丢失上一句 KFC 上下文。
- 商品名中的合法 `【夜宵专享】` 前缀会被旧安全检查当成不安全括号。
- 外卖训练只有模型主动输出隐藏记忆标签时才保存，明确自然语言偏好没有确定性兜底。

## 修复

- 品牌-only KFC 请求不创建残缺任务，由角色自然询问具体选择。
- 最近一轮是 KFC 时，“随便点／你决定／都可以／四件套／套餐”会补全为 `门店=肯德基；商品=吃堡堡4件套`。
- 商品字段允许配对完整的中文装饰前缀，门店字段和未配对括号仍会被拒绝。
- 明确、长期、可执行的偏好与忌口直接保存；一次性“今天想吃”不会写成长期偏好。
- 网页和私人 bundle 的 `delivery.js` 保持逐字节一致，并加入永久发布守卫。

## 验证边界

- 相关外卖回归 70/70 通过；外卖电脑服务 160/160 通过。
- 发布前继续执行完整测试、私人云备份链、版本一致性和覆盖包解包反向校验。
- 本轮没有代替用户创建真实订单、加入购物车或付款。Windows 源码与覆盖包验证不能替代 Mac 编译签名和真实 iPhone 安装验收。
