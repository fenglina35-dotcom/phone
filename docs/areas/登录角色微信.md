# 登录角色微信（以角色身份看 / 发 ta 的微信）

## 现在是怎么工作的

- 入口 `hisLoginOpen` → 会话状态 `_hisLogin`；页面 `hiswx`（列表）、`hischat`（单个聊天，`renderHisChat`）。
- 数据在 `S.hisWx[角色id]`（`hisWxData`）：`friends[]`，每个好友 `{id,name,alias,relation,relKey,persona,msgs[]}`；
  消息 `{r:'me'|'ta', c:正文, t, mine?, type?, _hisPaymentId?}`。`r:'me'` 是角色本人（右侧）。
- `hisSeed(cid)` 每次打开都会跑，负责把三处来源并到 `friends`：
  1. 「查他手机」的微信快照 `S.spy[cid].wechat[]`（`{who,relation,lines:['他：…','对方：…']}`），
     由模型在每次刷新查他手机时**整份重写**（`app.js` 里 `S.spy[id]=data;hisSeed(id)`）；
  2. `c._gotFromMe`（你介绍给 ta 的好友）；
  3. 关系网（`relHisFriends` / `relFamilySync`），会按别名、亲属称谓把重复的好友条目合并。
- 你用角色身份发的消息（`hisChatSend` / `hisChatAppend`）和好友的自动回复（`aiHisFriendReply`）
  同时写进 `f.msgs` 和查他手机快照（`hisSpyFriend(...).lines.push`），两边互通。

## 踩过的坑

- **聊天一段一段重复（v1742 修）**：快照没有消息 ID，只能按正文对齐。以前按「方向+原文」逐字比对，
  模型重写快照时同一句话多一个空格、全角/半角逗号不同、或把角色写成简称（「裴：」会被认成对方），
  就被当成新消息再追加，每刷新一次查他手机就多一段。现在用 `hisMsgKey`（NFKC、去空白/标点/零宽字符、
  不看说话人）按出现次数补齐；`hisCollapseRepeats` 在每次 `hisSeed` 时把已经存进去的连续重复段落收起
  （2–12 条一段，或单条较长的话；图片、表情、转账、红包、带付款记录的不动；「好」这类短回复不动）。
  守住它的测试：`tests/role-wechat-no-repeat-v1742.test.mjs`。
- 导入的正文要 `trim()` 后再存：前导空格在气泡里看不出来，却会让比对失效。

## 试过但失败的办法

- 逐字比对 + 出现次数（v1742 之前）：对模型重写的快照不够稳，见上。
- 只按好友名字比对、不合并关系网别名：会出现两个「妈妈」，后来由 `relHisFriends` 合并解决，不要拆掉那段合并。
