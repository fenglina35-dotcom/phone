# 第二百六十次安装：v1128／iOS 1.0.260 备份与线下回复失败依据修复

## 本次安装包身份

- 当前网页核心：v1128
- 私人 iOS：1.0.260 (260)
- 原生桥契约：25
- Xcode Scheme：`PhoneCompanionTest`
- 源码性质：基于线上 v1128 提交建立的独立干净打包提交
- 验证边界：Windows 自动检查和 ZIP 反查已执行；Mac 编译、签名、覆盖安装和真实 iPhone 验收仍待完成

## 本版修复的两个问题

### 1. “立即备份本机”原生请求超时

- 完整备份不再一次性塞进单个 `account.backup.upload` 原生消息。
- 网页与私人入口使用 `begin / chunk / commit / cancel` 分块传输，分块不会拆断 Unicode 代理对。
- iOS 在后台线程准备并校验上传内容，避免大备份长时间占用主线程。
- 备份上传原生等待为 120 秒，提交桥接等待为 150 秒；真实失败仍显示原始错误，不伪装成功。

### 2. 线下回复失败但没有可查看依据

- 单次约会请求明确使用当前角色选择的模型和路线。
- 只有没有 HTTP 状态的真实连接失败会在同一路线上自动重试一次；鉴权、余额、限流等 HTTP 错误不会盲目重试。
- 如果仍失败，“查看上一轮拦截内容”会显示“上一轮回复失败依据”，包括路线、模型、失败阶段、等待时间、重试次数和原始传输错误。
- 请求在模型正文返回前失败时，会明确说明不存在“被拦截正文”；不会制造固定角色回复，也不会把网络错误写进聊天或角色记忆。

## 覆盖安装步骤

1. 在 Mac 上新建目录，完整解压本次 ZIP；不要覆盖任何旧工程目录。
2. 用 Xcode 打开 `PhoneCompanionTest.xcodeproj`。
3. 选择 `PhoneCompanionTest` Scheme、真实 iPhone 和正确签名，然后 Run。
4. 必须直接覆盖安装，**不要先删除手机上的小手机 App**。
5. 安装后在 App 设置页确认同时显示 `v1128 · 备份与线下回复修复版` 和 `1.0.260 (260)`；不是这两个版本就不是本包。

## 真机验收

1. 在“授权与数据”点击“立即备份本机”，确认不再出现 `account.backup.upload` 的 60 秒原生请求超时，并确认云备份时间真实更新。
2. 正常发起一次单次约会回复，确认使用该角色配置的路线。
3. 只有真实遇到连接失败时，再打开“查看上一轮拦截内容”，确认显示“上一轮回复失败依据”和实际错误；不要为了制造失败故意改坏密钥或清除数据。
