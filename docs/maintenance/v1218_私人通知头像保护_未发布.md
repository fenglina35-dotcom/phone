2026-09-09。用户确认聊天照片仍在，仅后台通知显示圆形昵称首字，授权直接修复。

范围：私人版本。公开网页、公开 North 原生工程与公开云不修改。不提交、打包、推送或部署。本地私有网页候选 v1218；原生仍 iOS342 / 桥37，正式打包另升安装包身份。

## 已核实与未核实

- v1216 私人源码 ZIP 包含通知扩展 Swift 和 Info.plist，内容与现有源码一致（仅换行编码不同）；不能据此证明用户签名安装产物没有问题。
- 历史 v904 只补了缓存未命中时读 IndexedDB。现有 helper 在读取为空、解码失败或超时后仍会生成首字 JPEG；profile RPC 无条件更新 avatar_data，可把旧照片替换成占位图或空值。旧实现的故障注入已复现。
- 尚未取得该手机故障时的原始头像数据和网络响应，不能把此次真机具体触发因素说成已经证实；也未排除系统通知扩展下载失败。

## 定向修改

私人通知上传调用 serializer 的 notificationPhoto 模式：等待读图上限 5 秒、解码上限 5 秒；已配置照片失败时返回空值，不生成首字替代。真实好友头像调用不传此模式，保持原有回退。读取期间角色换头像时丢弃过期图片。正常照片和用户主动选择的 emoji/文字头像可更新。

私人云新增独立 before-update trigger，只在 automation_config.notificationAvatarPreserve 为 JSON true 且新头像为空时保留当前行旧头像。原 RPC 的鉴权、角色键、记忆、定时、主动开关保持不变；无标记旧客户端逻辑不改。不跨角色或账号找图，不记录图片正文、密钥或头像 URL。已有首字图会在下一次照片读取成功并同步时覆盖恢复。

## 验证与交付边界

专项验证包含缓存未命中、读取失败、读图超时、解码失败/超时、画布导出失败、超限、恢复、主动关闭、正常 emoji、好友旧回退及异步换头像。实际私有页面用真实 IndexedDB 和 Canvas 生成照片、读取像素，验证故障后不上传字图、恢复后重新上传；仅 RPC 为隔离夹具。

隔离 PostgreSQL 引擎运行原始 profile RPC 与迁移，先复现空值覆盖旧照片，再验证同一行保留、正常替换、错误密钥拒绝、角色隔离、记忆更新、定时保持和关闭主动联系、重复迁移。没有连接真实账号或修改远端库。

发布顺序是先私人云迁移并核验，再新私人客户端。缺少迁移不得分发本候选；不能把本地测试写成线上或真机已修好。旧系统通知不撤回、不改写。没有成功头像可保留时，照片仍需一次实际成功读取。公开原生现场完整保留。

最终本地结果：全仓 1730/1730；专项 11/11；双入口授权聊天门禁通过、页面错误0；真实私有页面头像照片像素验证和隔离 PostgreSQL 原 RPC/触发器验证通过。后续真实 iPhone 新通知仍待验收。Word Bug记录已按维护技能追加且校验旧段落保留，未作为排版成品交付。
