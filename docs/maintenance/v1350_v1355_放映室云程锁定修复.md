# 网页 v1350 / 私人源码 v1355（未打包）：App 名对不上导致锁定静默失败

## 现象
角色说“锁上了/锁了”，放映室实际没锁；用户多次指出，角色仍坚持已锁，也没有任何提示。

## 根因
`APPNAME2KEY` 别名表缺少 `放映室`（cinema）与 `云程`（travel），`_appKeys` 只查别名表，于是 `[锁定|放映室]` 解析为空、静默失败。这是早就存在的问题；v1348 的回头确认即使拿到正确指令也执行不了。浏览器复现：已授权放映室、确认回 `[锁定|放映室]`，旧代码仍未锁定、无提示。同类风险：角色写的 App 名与列表稍有出入（如“放映厅”）同样静默失败。

## 修复
- `_appKeys`：别名表查不到时按 `LOCKABLE` 显示名反查。
- `controlResolveUnknownApps`：锁定/解锁/限时/加时指令里的名字本地仍找不到时，调用一次辅助模型把名字对应到“已授权内置 App + 已选伴生 iPhone App”列表中的一个，再执行；对不上则提示。
- 名字认得但未授权：不调用模型，直接留提示“没有授权给ta，没有执行”。
- `controlClaimConfirm`：确认时没给出指令（或 `[不执行]`）留“嘴上说了…但实际没有执行”；指令给了但目标失败由上面两条提示负责，不重复。
- 真实执行成功仍留“🔐 锁定了「…」”。

## 验证
- 新测试：每个可锁 App 名都能解析（旧代码失败、新代码通过）；确认无指令时留提示。
- 浏览器（网页/私人）：“放映厅”经一次对照调用后锁定；未授权不调用模型并提示；不存在的 App 调用后提示；普通 `[锁定|音乐]` 不额外调用；云程可锁。
- 用户要求：未明确要求不打包，本轮只推送网页 v1350 与私人源码同步。
