# 第一百四十五次安装：v1024 低功耗定位生命周期与发热修复

## 本次版本

- 网页：v1024
- 私人 iOS：1.0.145（145）
- 原生桥：25
- 工程目录：`SmallPhone_v1024_LowPowerLocationLifecycleRepair`

## 本次只修什么

v1023 真机仍然持续发烫、点击严重延迟，证明“伴生快照写入放大”不是主要根因。本次依据真机出现的系统定位箭头和 Git 历史继续追查，确认私人 App 从 v891 起就可能在一次位置读取或打开伴生管理后，长期保持最高精度连续定位，并在每次回调中重复整理、写入足迹。

v1024 不删除真实定位和后台足迹：

1. 后台足迹改用 iOS 低功耗的显著位置变化服务，不再全天保持最高精度连续 GPS。
2. 角色或用户明确查询位置时，只请求一次精确定位；成功或失败后结束这一轮高精度工作。
3. 合并同时到来的重复精确定位请求，避免一次查看触发多轮 GPS。
4. 足迹回调不再重复从 `UserDefaults` 解码同一份数据；没有实际变化时不再重写。

## 不能误写成已经完成

- Windows 已通过 Swift 源码静态契约和全量自动回归。
- 尚未在 Mac/Xcode 编译、签名。
- 尚未在真实 iPhone 验证降温、点击响应和定位箭头生命周期。
- 因此本包是定位根因候选验证包，不能提前写成“真机已经修好”。

## 安装与单一验收步骤

1. 在 Mac 的全新目录完整解压本包，不要覆盖任何旧工程。
2. 打开 `PhoneCompanionTest.xcodeproj`，选择 `PhoneCompanionTest` Scheme 和真实 iPhone。
3. 先执行 `Product → Clean Build Folder`，再用原私人签名编译安装。
4. 覆盖安装，不删除旧 App、不清数据。设置页核对网页 v1024、私人 iOS 1.0.145（145）、原生桥 25。
5. 打开小手机停留在主页 5 分钟：记录系统定位箭头是否长期存在、手机温度是否继续上涨、点击图标是否仍有长延迟。
6. 再让角色明确读取一次位置，确认能得到真实新位置；读取完成后继续观察定位箭头是否结束或降为低功耗状态。

若仍发烫，不继续猜测或叠加性能开关；保留准确时间和当时定位箭头状态，下一步采集 Xcode Energy Log／Instruments Time Profiler，定位真实线程与调用栈。
