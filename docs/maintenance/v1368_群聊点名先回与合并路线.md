# v1368（网页）群聊点名先回、合并调用走角色路线

仅网页；私人包仍是 v1365 / iOS 1.0.424。

## 用户反馈
群里两个角色都设成「合并」后一发消息就提示「群里没人回上：HTTP 500：服务端内部错误（upstream error: do request failed）」；把其中一个调回「单独」，单独的能回、合并的不回。另外：我点名或 @ 的角色必须先回，然后才是情侣角色；没点名才是情侣角色先回。

## 原因
- 单独调用走角色自己设置的路线（v1362 起），合并调用却走全局当前路线；她全局当前那条路线的上游在报 500，所以合并的一直失败。
- 回复顺序写死了情侣角色第一，点名只认本名，不认备注和群昵称。

## 改动
- 合并调用用这一批里第一个人自己的路线；合并那一次请求失败时，这几个人退回每人单独调用，不再全体沉默。
- 点名（名字、备注、群昵称，包括 @）的人按在这句话里出现的先后先回，然后情侣角色；没点名时情侣角色先回。

## 验证
浏览器 + 假服务器（全局路线 500、角色路线正常）：两人都合并能回；「小助手…先生…」小助手先回；没点名情侣先回；合并请求 500 时两人都改成单独回复。
