# 角色唱歌与双歌单

## 结构与数据

- 音乐首页和歌单弹窗使用“我的歌单 / 他的歌单”；演唱角色是透明、无边框、随名字收缩的文字选择。通话不增加停止唱歌按钮，沿用原有输入和挂断。
- 原歌曲无 roleSongOwner，继续属于我的歌单；角色曲目按联系人ID隔离。roleSongReady=true才是已制作的演唱。原曲默认保留，另建演唱条目，原曲不能冒充成品。选择成品时若文件识别为不支持的录屏/视频，会保留表单并明确报错，不得静默保存为待转换或触发转换。
- roleSongHasAccompaniment区分含伴奏原曲和纯人声；roleSongAliases和roleSongMood用于点唱。roleSongConvertedFrom绑定原曲指纹，roleSongConversionConfig记录模型、变调和不透明配置修订号；不含地址或密钥。调变调后显式制作会产生新演唱；不变的参数复用已有版本，历史演唱不自动覆写。
- 复用原音乐上传、IndexedDB完整写入/回读/签名/可播放探测、导入导出和修复。上一首/下一首限定当前播放曲目的所属歌单。缺失或删除的拥有者保留数据，不自动分配给其他角色。

## 点唱与播放

- 明确点名成品（如“我想听小星星”“给我唱小星星”）或要求随机唱歌时，roleSongRequestPlan从当前角色已完成演唱生成文件动作，aiReply直接走原真实音频语音快照，不请求聊天模型或普通TTS；不依赖模型写对唱歌标签。歌词、否定、卡片和其他任务不抢占，找不到唯一成品仍交原对话处理，不转换。
- 语音/视频callAI使用同一请求动作，仅接受本通话当前用户消息，连接/巡检/画面/静默续聊不重复点唱；记录已消费消息ID。播放前及异步后校验成品来源快照。直接歌曲不走外语台词修正或视频动作补全，普通通话规则保留。角色自主唱歌标签继续兼容。
- 旧原曲ID可映射到本角色同名的已完成演唱，同名成品优先手动上传的版本，提示词也据此去重。不同歌名的别名冲突仍不擅自选择。点唱只播放已完成演唱；原曲只有音乐编辑里的明确制作操作才能转换。
- roleSongPrompt按当前角色过滤候选，显式点唱时优先匹配歌名/别名，再限制最多40首；旧曲目不会被窗口漏掉。无显式点唱时只允许角色自主选已完成演唱，不暗中制作原曲。
- 协议为单独一行[唱歌|歌曲ID]，也支持唯一歌名/别名和随机。没有导入的歌不伪称已唱好，不自动搜索、购买或下载音源。
- 明确点唱且当前角色有可用演唱时，roleSongRequestAvailable关闭“必须合并成普通语音”的强制提示和格式修正；普通说话、空歌单、只有其他角色曲目、仅有原曲时沿用原语音规则。避免“用语音给我唱”把[唱歌|ID]再次送模修正成[语音|歌词]。
- 微信aiReply在有效回复代次中读取真实音频，保存独立聊天快照，再显示可播放语音；每轮最多一首。唱歌绕开TTS、语音导演和3D处理，语音长度跟随实际音频，不受普通TTS的60秒上限及缓存TTL重新朗读影响。
- 普通、视频、共同生活通话的callAI共用歌单；角色短台词后播放演唱，复用playCallMediaWait及原生/浏览器回退。新用户轮次、挂断、账号或会话变化取消当前播放；迟到原生返回不能重新启动网页回退。歌曲在回放里保留实际音频，不进台词重新配音。
- 读取、解码、保存或播放的各次await后复核账号、联系人、歌曲拥有者、来源、角色状态及请求有效性，避免迟到结果进入错误会话。删除原歌曲不使历史演唱快照自动变成TTS。

## 手机发起云端翻唱

- 需要实际云端算力，Mac不用常开。用户已授权其个人Modal工作区的推理模型、索引和小星星测试素材，不上传原始克隆录音、训练数据或聊天。公开代码不包含个人服务地址、密钥或音色权重。
- 每角色配置位于S.settings.roleSongCloud[cid]，可导入连接JSON，必须经health验证；留空密钥可停用。任务编号在S.settings.roleSongJobs，不随音乐导出包导出。明确点歌曲编辑里的“制作他的翻唱”时才转换、回读验证并另存演唱；微信和通话不调用转换，播放时音频逐字节保持上传内容。
- API只接受无账号密码、查询或片段的HTTPS服务地址；Bearer密钥保护所有业务路由。任务获取另需其HMAC凭证。源文件上限32MB/6分钟；固定FFmpeg解码只开file/pipe协议。含伴奏素材用MDX提取Vocals，再RVC，输出纯人声MP3。
- 请求不自动重发。已有任务时重载或再次明确点制作继续获取；明确422失败释放失败任务，保留原曲，等用户再次显式重试。网络结果不明时保留编号，不把失败假装成完成音频。
- 私有脚本位于 /Users/zoushijie/Downloads/角色唱歌/cloud_song.py。固定Applio提交59c113106c0dfff647324ab1a80c286f17b51929、Torch/torchaudio2.11.0、CPU torchvision0.26.0、audio-separator0.48.0。仅逐项挂载推理模型/索引及公共基础模型。
- convert负责解码、可选分离和合成；每30秒加0.3秒上下文交给独立convert_part，最多6个CPU任务并行，单次输入容器，接缝5ms淡入淡出。进度Dict只存输入指纹和各段任务编号，容器被抢占时复用已保存任务；7天无读写由平台过期。不要仅依靠retries=0：平台抢占仍会重启相同输入。
- 当前个人试验只用免绑卡1美元额度，上限由Modal设定；T4部署实测被要求绑卡而拒绝。绑卡前无法在本账号先设净扣费上限0，不能承诺绑卡绝不扣费，所以未绑卡。CPU/内存是Functions计算，不使用按token另计费的Shared Endpoints。
