## 已确认差异

公开工程 1.0（8）的屏幕使用时间回包有 reportAvailable / generatedAt / totalSeconds / apps，但没有私人新增的 usageDay / usageRevision / timeZone。现有私人解析器要求 usageDay 为今日，直接复用会拒绝公开有效回包。适配不能推断不存在的设备时区或把上传时间冒充采集时间。

公开线上项目 lkhlyfpssmrjkkzhuzag 已查到 phone-role-push v37 和 phone-companion-push v9。它们的版本号与私人项目不可比较；须下载代码并检查数据库依赖后决定迁移方案，不能直接覆盖。

## 本轮只读核验与适配初稿

公开数据库已只读核对函数列表及表结构，没有执行迁移。公开已有配对、快照、命令、后台任务和收件接口，但缺少新版 phone_role_push_attempts 表、诊断列及 phone_role_background_complete_turn 接口。公开函数源码下载到隔离 .qa 目录，未覆盖仓库或线上代码。

新增 public-north-policy.js 为无网络的纯函数适配初稿：接受公开旧屏幕报告格式但不推断设备使用日；仅允许步数健康字段进入事实；缺失值不强转为零；新旧设备/序号检查；角色授权与前后台可共用的提示词。公开 Swift 将读取失败的步数也编码为0，因此单独标注零步不确定性。模块还没有加载到任何运行入口，不代表迁移已完成。

实际能力冲突：公开 ContentView.unlockAllManuallyLockedApps 只改本地锁定集合，没有私人 CompanionSyncView.recordExplicitManualUnlock / automationEvents 上报链。网页不能根据锁态变化假称用户手动解锁。用户已明确确认“没有的功能就不迁移，有的话全部迁移”，因此该事件承诺不迁移；不再等待重复确认，也不扩大公开原生上架范围。

专项检查包含真实旧 parser 拒绝公开 reportAvailable/totalSeconds/generatedAt 格式的反例、新适配通过、null/缺失/0区别、授权限制、健康白名单、旧或异设备回包拒绝、手动解锁不归因。尚未网页交互、核心聊天全量回归、云端迁移或真机联动。

后续适配初稿补充：公开位置/足迹保留设备原始时间，不用上传时刻替换未知采集时间；权限单独控制。命令构造只接受该设备稳定 App ID、明确授权和公开原生实际支持的动作及 1—720 分钟限额，不以名称猜 ID。仍为未接入运行入口的纯函数模块，不能称迁移完成。
