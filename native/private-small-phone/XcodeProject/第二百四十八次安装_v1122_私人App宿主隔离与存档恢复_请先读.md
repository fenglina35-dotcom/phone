# 第二百四十八次安装：v1122 / 私人 iOS 1.0.248（248）

## 先保护现有数据

1. 不要删除当前“小手机”App，不要清理页面缓存，不要退出手机号。
2. 如果聊天或主屏组件刚恢复，先不要点“立即备份本机”，避免用残缺状态覆盖较早的保护副本。
3. 本包必须使用同一个 Bundle ID 覆盖安装；覆盖安装会保留 App 容器，卸载会删除容器。

## 本次只改私人 App

- 私人完整页面仍为 v1122，原生桥仍为 25。
- 私人 iOS 升为 1.0.248（248）。
- Screen Time 报告改由固定 UIKit 宿主按需挂载，不再改变承载 WKWebView 的 SwiftUI 根结构。
- 状态栏主题只有真实变化时才通知根视图，启动时直接使用上次保存的主题。
- 增加 Coordinator、WKWebView、进程会话和报告挂载诊断，便于判断偶发卡顿究竟属于宿主重建、WebContent 终止还是进程重启。
- 本机恢复会先列出可读候选，包括原生保护副本；玻璃主题组件管理可真实恢复三个主屏组件。
- 没有修改公开网页，没有删除聊天、图片、角色、密钥、组件配置或现有原生存档。

## 在 Mac 上编译安装

1. 把 ZIP 解压到一个全新文件夹，不要覆盖以前解压的工程。
2. 打开 `PhoneCompanionTest.xcodeproj`。
3. 为主 App 和所有扩展选择同一个开发者团队，选择真实 iPhone。
4. 直接运行并覆盖手机上现有 App；不要先卸载。

## 先恢复聊天和组件，再做性能验证

1. 打开“设置 → 授权与数据 → 恢复所有数据（扫描本机存档）”。
2. 只看候选列表，不会自动恢复。选择事故前时间正确、聊天数量最完整的一份，再确认。
3. 恢复后先检查角色聊天、头像、图片和主屏组件。组件仍缺失时，在玻璃主题组件管理里点“恢复三个主屏组件”。
4. 全部正确后，才手动建立一次新备份。

## 卡顿验证

1. 冷启动后保持前台至少两分钟，连续打开微信、共同生活、设置和主屏应用。
2. 观察点击延迟、白屏／屏保跳转、温度和后台消息。
3. 若再次出现，复制私人 App 性能诊断。重点保留 `processSessionID`、`coordinatorID`、`webViewID`、`native.webview.dismantle`、`native.webcontent.terminated` 和 `native.usageReport.mount/unmount`。

## 验证边界

Windows 侧只能验证源码语法、版本、私人入口测试和 ZIP 逐文件完整性。尚未在 Mac 编译、签名，也尚未经过真实 iPhone 长时间验证，因此本包是证据驱动的候选修复，不得写成“真机已经彻底修好”。
