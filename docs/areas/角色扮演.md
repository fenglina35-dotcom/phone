# 角色扮演

角色扮演复用单次约会的显示组件，不复用现实约会状态。入口 `rpOpen`、`rpSaveSetup`、`rpCreateInviteFromAI`；数据仍在 `S.roleplay`，旧摘要保留。本局日期和虚构身份保持独立。共同生活剧场会读取现实关系、在场状态和生活联动，所以保留原角色扮演的多人房间，不将其整体搬入。

## 页面和输出

`renderRP` 和 `renderOff` 共用 `renderDateScene`，使用共同生活原有的 `offstage`、`offmsg`、`offbubble`、`offnar` 和 `offRevealText`。不再给消息附加旧 `rpmsg`、`rpbubble`、`rpnar` 样式类，避免旧角色扮演样式覆盖原气泡。`rpThemeContact` 复用约会外观生成函数，但外观存于剧情数据，不修改约会配色。模型与路线由 `rpReplySettings`、`rpRequestOptions` 独立配置；初次沿用旧副模型设置，之后以剧情设置为准。

按用户最新要求，角色扮演直接复用共同生活的 `offlineFormatPin` 和实际生效的 `modelUnfilteredOfflineItems`，原文输出参数也一致；非原文分支调用原 `offReplyItems`。`rpReplyItems` 仅在原解析结果上附加参演角色 ID、去掉已识别的姓名前缀，不再自己拆括号、判断动作、切引号或过滤正文。单人直接输出台词；多人只在台词行加姓名，旁白仍单独成行。角色邀请生成的 opening 字符串也采用同一个格式提示。不得为了角色扮演去改共同生活已稳定的解析实现，更不能调用其现实生活状态、查看手机或控制设备的副作用。

## 存档和记忆

`rpArchiveRecord` 先保存完整消息快照和基础摘要；结束时 `rpEnd` 等待 `saveNowAsync` 成功，再离开并异步调用 `rpSummarizeArchive`。模型失败或关闭页面不会使原文依赖总结结果。旧存档没有原文时明确说明，不能伪造补回。新开局的手动配置和角色邀请两个入口都保护旧内容。

`rpSyncArchive` 将“共同玩过虚构剧情”的记忆写入参演角色，使用 `summaryList` 隔离账号；不能把虚构身份写成现实关系。删除存档也删除对应记忆副本，重试总结不得让已删除记录复活。异步结果检查原状态、账号和记录仍存在。

验证：`tests/roleplay-open-v1384.test.mjs` 包含旧版必败的“模型仍等待时原文已保存”回归，以及双端页面、旁白分离、多人归属、编辑、滚动、失败原因和正常入口重载恢复。`tests/permanent-fix-guard.test.mjs` 保留三个功能标记。真实模型质量和真机效果以发布记录为准。
