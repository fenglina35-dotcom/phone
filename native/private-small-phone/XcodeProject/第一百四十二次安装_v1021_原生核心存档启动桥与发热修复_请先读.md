# 第一百四十二次安装：v1021 原生核心存档启动桥与发热修复

## 本次版本

- 网页：v1021
- 私人 iOS：1.0.142（142）
- 原生桥：25
- 工程目录：`SmallPhone_v1021_NativeCoreBootBridgeRepair`

## 本次查明的上游原因

- v1020 真机仍会出现：首页外壳能显示，但自定义图标和相框图片整批空白；点击延迟很长；温度继续上升；后台角色消息也不再进入聊天。
- 这些首页图片本来全部属于启动必读图片。它们一起不出现，说明启动恢复并未结束，而不是每一张图片分别损坏。
- 原生 App 读取大容量核心存档后，旧桥接会把整份存档转义并拼成一段巨大的 JavaScript 源码，再让 WKWebView 主线程编译执行；存档越大，主线程开销、内存副本和超时风险越高。超时后恢复链还可能继续读取副本。

## 本次修复

- 核心存档仍在原生后台存储队列读取，不更改存档格式和用户数据。
- 大存档改用 WebKit 官方参数通道传给固定的小函数，不再把存档正文当 JavaScript 源码编译。
- 启动尚未完成时，不启动伴生状态轮询、后台收件补拉和好友同步；核心与启动图片恢复完成后，立即补做真实伴生和后台收件同步。
- 保留 v1020 的已缓存图片同步注入、缺失图片分批读取与退避，避免下游重复读库重新出现。

## 不得回退

- 不得清除、重建或伪造用户核心存档和图片数据。
- 不得改动朋友圈真实模型回复、后台通知与消息落库、普通微信、通话、真实伴生数据、共同相册和语音隔离。
- 不得用固定文案冒充角色消息，不得修改用户外置语音的 base、key、model、voice。
- 根目录与私人 `PhoneWeb.bundle/app.js` 的既有通话布局差异继续保留，禁止整文件互相覆盖。
